# Atlasnote Skills 能力地图与应用研究

本项目分析 [Atlasnote Skills 目录](https://atlasnote.ai/zh-CN/skills) 收录的 81 个模块分别代表什么能力、依靠什么机制生效、怎样组合使用，以及这些模式对个人 Agent 工作流有什么参考价值。

这里研究的不是截图，也不是界面审美。页面只被当作一个能力样本库；原有界面审计已降为附录。

> **归档状态：暂时归档（2026-08-31）。** 当前研究、核验报告、交互工作台和项目内元技能已形成可复现快照；暂不继续扩展条目。若 Atlasnote 的目录结构明显变化，或要把某个候选真正安装并用真实任务评测，再重新启动本项目。

[在线打开能力地图](https://yydshly.github.io/0830_codex_project/demos/atlasnote-skills-page-analysis/) · [查看 Atlasnote 原网页](https://atlasnote.ai/zh-CN/skills) · [查看 GitHub 项目目录](https://github.com/yydshly/0830_codex_project/tree/main/projects/atlasnote-skills-page-analysis)

## 结论先行

Atlasnote Skills 最有价值的理解方式是：

> 一个 Agent 能力模式库：它把散落在开源生态中的方法、工作流、工具连接、模板、质量门和知识系统，翻译成可以按任务理解的中文目录。

最重要的结论是：**81 个模块并不是 81 个同质的 Skill，也不等于给模型增加了 81 种智力。**它们主要通过以下机制增强 Agent：

- 把专家经验写成可重复步骤；
- 把任务拆成有顺序、有停点的工作流；
- 用 CLI、脚本或 MCP 接入真实工具；
- 用模板和设计系统约束交付物；
- 用规则、测试和人工确认建立质量门；
- 用知识图谱、文件或上下文底座保存长期信息；
- 用路由器和元技能决定何时加载哪项能力。

它们可以组成一条完整能力链：

```text
任务定义 → 路由与规划 → 专业方法 → 工具执行 → 质量验证 → 交付物 → 记忆与改进
```

对个人最有参考价值的不是把 81 项全部安装，而是看清自己的工作链缺在哪一环，再借鉴相应模块的结构，把有效做法改造成自己的 Skill、命令、模板或检查器。

## 研究问题

- 每个模块究竟给 Agent 增加了什么可观察能力？
- 它依靠说明文件、工作流、脚本、CLI、MCP、模板还是质量门生效？
- 哪些模块可以组合，组合后覆盖工作链的哪一段？
- 什么任务适合直接采用，什么情况只值得借鉴结构？
- 对正在使用 Codex 的个人，最小而有效的能力栈是什么？
- 如果把这些能力做成平台，最值得扩展的基础设施是什么？

## 方法

本研究在 2026-08-30 至 2026-08-31、未登录状态下完成：

1. 抓取目录当前 81 个条目的标题、摘要和详情链接，建立完整清单。
2. 不按网页分类照抄，而是按“能力形态 × 业务领域”二次编码。
3. 用 Agent Skills 的结构解释其生效原理：触发、说明、资源、工具、验证和渐进加载。
4. 从九种能力形态各取一个代表，核对 Atlasnote 实际链接到的官方仓库，再记录真实类型、至少两项官方事实、未验证项、前置、权限、许可、维护信号和采用判断。
5. 用“能否改变 Agent 的行为、访问范围、交付物或成功判定”评价真实能力。

## 关键发现

### 1. “Skill”本质上是能力包装，不是新模型

它通常不改变基础模型参数，而是把“什么时候做、按什么步骤做、调用什么工具、交付什么、怎样验收”封装起来。能力提升主要来自上下文、流程、工具和反馈，而不是模型突然学会了新知识。

### 2. 81 项覆盖的是完整工作系统，而非 81 个提示词

其中既有 65 行行为约束，也有多阶段交付流水线、浏览器 CLI、n8n MCP、PPTX 生成器、设计系统、知识图谱和 Skill 诊断器。安装方式、运行边界和风险完全不同。

### 3. 最强的模块往往同时包含“方法 + 执行 + 验证”

只有文字规则的 Skill 能指导模型，但稳定性有限；带 CLI、脚本或 MCP 的模块能真正操作外部世界；再加测试、阻断清单、dry-run 或人工确认，才形成可交付闭环。

### 4. 组合的关键不是数量，而是职责互补

一个好的组合通常只需五类角色：目标/规格、领域方法、执行工具、质量门、复盘改进。重复安装同类大合集只会增加触发冲突、上下文和维护成本。

### 5. 对 Codex 用户，长期价值是形成自己的能力资产

目录适合做侦察和模式学习。更有效的路径是：从重复任务出发，借鉴 2～3 个候选的结构，在项目范围试用，用真实任务评测，最后保留最小规则并改成自己的版本。

### 6. 目录介绍与当前仓库会发生漂移

原仓库核验发现，Atlasnote 收录时写“59 条”的 Impeccable，官方当前 README 已写为 61 条；同一个目录里的 shadcn/ui 是组件源码平台，agent-browser 是 Rust CLI，Paper Search 是 Python MCP/CLI/Skill，SwarmVault 更是完整知识工具链。因此任何准备落地的候选，都必须在安装当天重新核对项目类型、依赖、脚本、权限和许可。
