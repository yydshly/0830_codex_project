一句人话：不是给 Agent 换了脑子，而是给它配了一份 SOP、一套工具、几张模板和一个质检员。

核心判断 真正成熟的能力，不只告诉 Agent “怎样做”，还说明 “何时用、用什么做、做到什么程度、失败怎么办”。

03 FOUR CLASSIFICATION LENSES

先分清它是什么，再决定怎样拿来用

同一个模块可以同时属于一个业务领域、一种能力形态和工作链的一段；“采用方式”回答的则是另一个问题：你应该直接用、与别的能力组合、只借结构，还是先完成外部集成。

  1. 01先说真实任务

    不要从热门模块出发，先描述最近一次返工或每周重复的工作。

  2. 02诊断能力缺口

    判断缺的是方法、工具、约束、验证、路由还是记忆。

  3. 03用四套分类定位

    领域看对象，形态看机制，链路看角色，采用方式看落地成本。

  4. 04用真实任务验证

    先做最小版本，只有结果更稳、更快或可证明时才长期保留。

SKILL MATURITY

从一句提示，到会自我改进的能力资产

成熟度不是文件数量，而是能力是否可重复、可执行、可验证、可从失败中更新。多数个人 Skill 先做到 L1 或 L2 就已经有价值。

  1. L0
    临时提示只解决这一次，没有稳定触发和交付定义。
  2. L1
    可复用触发、输入、步骤和输出可以重复。
  3. L2
    可执行能调用脚本、CLI 或连接器改变真实状态。
  4. L3
    可验证有测试、质量门、人工确认或失败判定。
  5. L4
    可改进保留来源和失败证据，用真实样本小幅更新。

06 ORIGINAL SOURCE VERIFICATION

网页告诉你“值得看”，原仓库才告诉你“它到底是什么”

这里从九种能力形态各取一个代表，核对真实项目类型、依赖、权限、许可证和维护信号。核验的是官方说明，不是假装已经替你安装跑通。

已证实

当前官方仓库或官方文档直接支持的事实。

未验证

介绍页或仓库的主张，尚未用独立样例复现。

未运行

本项目没有安装这些第三方项目，也没有授予其权限。

正在加载代表项目核验记录……

阅读规则：“官方来源支持”只证明仓库这样设计或记录，不等于本机可用、效果优秀或适合你的环境。安装前仍要固定版本、查看脚本、核对权限，并从一个可撤销的小任务开始。

    10 WHAT COMES NEXT

    从目录继续扩展，最值得做什么？

    方向不是继续增加卡片数量，而是把发现、组合、评测、安全和改进做成基础设施。

    01

    机器可读清单

    统一记录触发、输入、输出、依赖、权限、版本、许可证和验收。

    02

    能力图谱

    表达前置、替代、互补和冲突，从热门推荐转成最小能力链。

    03

    评测台

    用真实任务比较成功率、质量、时间、Token 和人工干预。

    04

    安全沙箱

    脚本与写操作先 dry-run，展示变更计划，再批准真实执行。

    05

    团队私有库

    增加负责人、适用项目、数据分级、审批、弃用与回滚策略。

    06

    反馈闭环

    从真实会话识别误触发、步骤冗余和验收缺失，持续改进。

    最终理解

    能力不是一段神奇提示词，
    而是目标、上下文、程序、工具、约束、验证和反馈的组合。
