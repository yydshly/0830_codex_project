# 技术 Spike 与开发路线图 v0.1

## 1. 原则

先验证最可能推翻架构的假设，再建设编辑器和完整产品。Spike 代码是可丢弃实验，不直接成为生产内核，除非经过设计评审和测试补齐。

## 2. Spike A：确定性仿真内核

### 假设

单进程事件调度与固定步长 Mover 可以在目标实体规模下达到 D2 复现，并支持暂停、事件单步、帧单步、倍速和尽快运行。

### 最小实验

- 合成二维世界；
- 两类实体和两个 Mover；
- 稳定事件队列；
- 独立 RNG 流；
- 运行 100 次同一 Manifest；
- 比较领域事件摘要和最终状态。

### 输出

- 吞吐、内存和倍速数据；
- 不一致事件定位；
- 事件顺序和浮点策略 ADR；
- 建议容量目标。

### 通过门槛

- 同平台同版本达到 D2；
- 暂停不推进状态；
- StepEvent/StepFrame 语义稳定；
- 新增无关实体不改变其他实体随机流。

## 3. Spike B：指令闭环

### 假设

UI 可以通过统一 Command 契约完成提交、校验、调度、执行、回执和审计，而不直接操作状态。

### 最小实验

- SET_DESTINATION、STOP；
- 正常、重复、过期、无权限、目标不支持和前置条件失败；
- 指令生命周期 UI；
- 同 command_id 幂等；
- 暂停时提交未来指令。

### 通过门槛

- 每个请求具有确定最终状态；
- 重复提交不重复产生领域效果；
- 失败原因机器可读且可显示；
- 回放能还原指令状态而不重新执行。

## 4. Spike C：态势投影与回放

### 假设

快照 + revision 增量可以在目标规模下稳定驱动地图、轨迹和时间轴，丢包后能够恢复。

### 最小实验

- 生成目标规模的合成实体运动；
- Projection 快照和 StateDelta；
- UI 拾取、轨迹、事件筛选；
- 人为丢弃增量并重新同步；
- 周期快照 + 事件跳转回放。

### 通过门槛

- UI 不读取内核对象；
- revision 断裂可恢复；
- 回放不重新运行仿真；
- 地图交互在目标刷新率下无明显卡顿；
- 记录真实事件量、快照大小和跳转耗时。

## 5. Spike D：插件边界

### 假设

可以在不修改内核的情况下安装第二个 Mover，并限制其能力和失败影响。

### 候选实验

分别验证进程内接口与一个隔离候选（WASM 或子进程 RPC）：

- 加载/卸载；
- 版本不兼容；
- 插件崩溃；
- 超时；
- 无网络和文件权限；
- 快照/恢复；
- 性能开销。

### 通过门槛

- 新插件不修改内核源码；
- 权限声明可执行而非仅文档；
- 失败策略可观察；
- 版本拒绝信息清晰；
- 性能和调试代价有量化记录。

## 6. 阶段路线图

### P0：Walking Skeleton

交付：手写资产配置、两个阵营、基础实体、指令、运动、态势、时间控制、事件日志和回放。

质量门：参考场景 16 步全部通过；相同 Manifest 达到 D2；无编辑器也能端到端运行。

### P1：内容生产

交付：模型包导入、最小地图编辑器、场景编排、Schema 表单、资产版本和验证夹具。

质量门：非内核开发者能创建第二场景；错误配置在运行前被阻止。

### P2：合成交互与指标

交付：有限状态机 Behavior、抽象 Interaction、结束条件、Metric 插件和结果摘要。

质量门：规则和指标全部版本化；不含现实模型；同场景批次结果可比较。

### P3：平台化

交付：插件 SDK、样例插件、兼容矩阵、资产目录、离线安装包、SBOM、升级与迁移工具。

质量门：第二个插件和第二个场景不修改核心；旧资产有明确兼容/拒绝结果。

### P4：实验与分析

交付：批量运行、参数组合、结果比较、报告导出和回归面板。

质量门：批次运行继承精确 Manifest；指标和失败可追溯到具体运行。

### P5：高级能力候选

分布式仿真、高保真模型、3D、受限 AI 助手、外部授权引擎适配都需要新的 Charter 和 ADR，不从 MVP 自动继承授权。

## 7. 首批 Epic

1. `SIM-CORE`：时间、事件、实体、组件、RNG；
2. `SIM-ASSET`：模型、地图、场景、版本和校验；
3. `SIM-CMD`：指令网关、生命周期和 Handler；
4. `SIM-MOVE`：Transform、路线和 Mover；
5. `SIM-PROJ`：状态投影、快照和增量；
6. `SIM-UI`：地图、选择、指令、时间与事件；
7. `SIM-REPLAY`：事件日志、快照、跳转和回放；
8. `SIM-SDK`：插件清单、Capability API 和示例；
9. `SIM-VV`：参考场景、契约测试、确定性和性能夹具；
10. `SIM-SUPPLY`：离线打包、校验值、SBOM 和升级。

## 8. 迭代顺序

```text
契约夹具
→ 无 UI 的内核跑通
→ 指令闭环
→ 状态投影
→ 最小地图 UI
→ 事件日志和回放
→ 第二场景
→ 最小编辑器
→ 插件 SDK
```

不要先开发完整地图编辑器；它会把团队锁在 UI 细节，而核心时间、事件、资产和复现风险仍未验证。

## 9. 团队职责

| 职责 | 首要责任 |
| --- | --- |
| 产品/领域负责人 | Charter、参考场景、非目标、内容安全 |
| 架构/内核负责人 | 时间、事件、状态、契约和 ADR |
| 前端/可视化负责人 | 态势读模型、地图交互、时间轴和编辑体验 |
| 平台/工具负责人 | 资产、插件、打包、离线运行和开发体验 |
| V&V/测试负责人 | 契约夹具、复现、回放、容量和回归 |

小团队可以一人承担多个职责，但评审时要显式切换视角。

## 10. Definition of Done

任何功能完成必须满足：

- 契约和 Schema 已版本化；
- 正常、失败和恢复路径有自动测试；
- 对参考场景无回归；
- 事件和错误可观察；
- 离线环境可以执行；
- 不绕过 Command/Event 边界；
- 文档说明适用范围和非目标；
- 不引入受限或来源不明的资产；
- 若影响确定性，更新 D2 证据；
- 若影响插件，更新兼容矩阵。

## 11. 下一次架构评审输入

完成四项 Spike 后，必须带以下证据评审：

- 性能与容量结果；
- D2 复现报告；
- 指令状态矩阵；
- UI 增量恢复录像或日志；
- 插件隔离对比；
- 更新后的 ADR-005 至 ADR-009；
- 是否继续模块化单体的结论；
- P0 实现技术栈建议。
