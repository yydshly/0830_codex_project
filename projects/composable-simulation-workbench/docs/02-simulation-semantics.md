# 仿真语义规范 v0.1

## 1. 目的

本规范定义所有模块必须共同遵守的时间、事件、状态、随机性、坐标、单位、指令和复现规则。技术栈可以改变，语义不能由各模块自行解释。

## 2. 核心不变量

1. 仿真状态只能由仿真内核在处理事件或时间步时修改。
2. UI、网络输入和插件不能直接持有并修改内核实体。
3. 所有外部操作必须转换为版本化 SimulationCommand。
4. 每次状态变化必须能够追溯到事件、指令、初始化或明确的时间步更新。
5. 墙钟时间不决定仿真结果，只控制运行节奏。
6. 暂停时仿真时间和实体状态不推进。
7. 相同输入、版本、种子和执行模式必须产生一致的关键结果。
8. 未被 Schema、单位和适用范围验证的数据不得进入运行。

## 3. 时间模型

### 3.1 三种时间

| 时间 | 定义 | 用途 |
| --- | --- | --- |
| WallTime | 现实世界时间 | UI、日志接收、性能观察 |
| SimulationTime | 仿真世界中的单调时间 | 事件、指令、运动和结束条件 |
| ReplayTime | 回放游标时间 | 读取历史状态，不修改仿真 |

任何业务事件都必须携带 SimulationTime；WallTime 只能用于运维信息。

### 3.2 运行模式

- Paused：不推进 SimulationTime；
- RealTime：按墙钟比例推进；
- Scaled：按指定倍速推进；
- AsFastAsPossible：不等待墙钟；
- StepEvent：处理下一个事件边界；
- StepFrame：推进一个配置的运动时间步。

运行模式变化本身也是事件并进入审计日志。

### 3.3 混合推进

第一版采用“全局离散事件 + Mover 固定/可配置步长”的混合方案：

```text
取下一个事件时间
→ 将需要更新的 Mover 推进到该时间
→ 按稳定顺序处理同一时间的事件
→ 生成状态变化和新事件
→ 更新只读投影
```

不得让每个组件自行读取墙钟或创建不可控线程推进状态。

## 4. 事件顺序

同一 SimulationTime 的事件按照稳定排序键处理：

```text
(simulation_time, phase, priority, insertion_sequence)
```

- `phase` 由内核定义，例如 Command、ModelUpdate、Interaction、Observation、Projection；
- `priority` 只能在同一 phase 内使用，取值范围固定；
- `insertion_sequence` 由单个内核实例单调生成；
- 不允许依赖哈希表遍历顺序、线程调度或网络到达顺序。

事件处理器不能递归直接调用另一个处理器；它只能生成后续事件。

## 5. 指令语义

### 5.1 生命周期

```text
Submitted
→ Validated / Rejected
→ Scheduled / Expired
→ Executing
→ Completed / Failed / Cancelled
```

每次迁移都产生 CommandStatusChanged 事件。Rejected、Failed 和 Expired 必须带机器可读原因码。

### 5.2 生效规则

- `effective_sim_time` 早于当前时间时，按命令类型选择拒绝或调度到当前事件边界；规则必须固定；
- 指令只作用于目标实体公开的 CommandHandler；
- 前置条件在执行时再次检查；
- 相同 `command_id` 必须幂等；
- 取消指令只影响尚未完成且声明可取消的命令；
- 任何插件都不能绕过 Command Gateway 修改状态。

## 6. 状态模型

### 6.1 权威状态

内核保存当前权威状态；态势显示和分析服务保存派生读模型。派生状态丢失时必须能从快照和事件重建。

### 6.2 组件更新

每个组件声明：

- 读取的状态；
- 可以写入的状态；
- 更新触发条件；
- 使用的时间粒度；
- 是否使用随机数；
- 产生的事件；
- 快照和恢复格式。

多个组件不能无约束地写同一字段。共享写入需要由一个拥有者组件或显式协调器负责。

## 7. 随机性

- RunManifest 保存主种子；
- 内核为每个实体/组件派生独立随机流；
- 新增一个无关实体不应改变其他实体既有随机序列；
- 禁止使用系统时间作为隐式种子；
- 所有随机采样必须经过平台 RNG 接口；
- 回放只读取已记录结果，不重新采样。

## 8. 坐标、单位与运动

第一版参考场景使用局部平面坐标：

- 长度：米；
- 时间：秒；
- 速度：米/秒；
- 角度：弧度，显示层可以转换为度；
- 坐标：右手局部笛卡尔坐标；
- 地图原点、轴方向和范围写入 MapSpec。

运动组件必须声明：

- 输入状态和指令；
- 运动学或路径模型；
- 最大有效步长；
- 适用范围；
- 越界和不可达处理；
- 碰撞/障碍处理等级；
- 插值方式；
- V&V 级别。

第一版只要求常识合理的 L1 运动，不以视觉平滑代替内核位置正确性。

## 9. 快照与回放

快照包含：

- SimulationTime；
- 事件序号；
- 场景和模型版本；
- 实体及组件权威状态；
- RNG 流状态；
- 待处理事件队列；
- 未完成指令；
- Schema 版本和校验值。

回放优先使用“周期快照 + 事件增量”：跳转到目标时间前最近快照，再重放到目标时间。回放环境不能接受会改变历史的仿真指令。

## 10. 复现等级

| 等级 | 要求 |
| --- | --- |
| D0 | 结果类别一致 |
| D1 | 关键指标和业务事件一致 |
| D2 | 全部领域事件顺序与载荷一致 |
| D3 | 逐状态/逐字节一致 |

MVP 目标为 D2。D3 只有在技术 Spike 证明跨平台浮点与序列化成本可接受后再决定。

## 11. 错误与终止

- 可恢复模型错误：隔离到组件并生成 ModelFault；
- 不合法指令：拒绝，不影响运行；
- 插件异常：记录、禁用或安全终止，策略由插件清单声明；
- 队列或状态不一致：生成 KernelInvariantViolation 并安全终止；
- 终止时仍要落盘最后可用快照、事件尾部和错误报告。

禁止捕获错误后静默继续并产生无法解释的结果。

## 12. 容量参数表

| 参数 | 待测值 |
| --- | --- |
| 活跃实体数 | 待定 |
| 每实体组件数 | 待定 |
| Mover 更新频率 | 待定 |
| 每仿真秒事件数 | 待定 |
| 目标仿真倍速 | 待定 |
| UI 状态刷新频率 | 待定 |
| 并行运行数 | MVP 为 1，后续待定 |
| 事件保留时长 | 待定 |
| 快照间隔 | 根据跳转时间和存储权衡 |

容量门槛必须由参考场景和合成负载测试得出。
