# 合成参考场景 v0.1

## 1. 目的

参考场景不是业务想定，而是整个产品的 Walking Skeleton 和回归夹具。它使用完全虚构的阵营、实体、地图和交互规则，验证“制作—运行—控制—显示—回放—扩展”全链路。

暂定名称：**双谷通行演示**。

## 2. 场景摘要

一张虚构二维地图包含两片出生区域、道路、开阔区、障碍区和一个中立目标区域。蓝色与红色阵营各部署若干通用移动实体。用户控制蓝方，红方由简单有限状态机控制。双方只产生“接触、阻断、通过、退出”等抽象事件，不模拟真实装备、战术或效应。

## 3. 场景资产

### 地图

- `map.synthetic-valley.v1`；
- 统一平面坐标和米制单位；
- 两个出生区、一个目标区；
- 一条主路、一条绕行路；
- 两个不可通行多边形；
- 不包含真实地理数据。

### 实体原型

| 原型 | 组件 | 用途 |
| --- | --- | --- |
| Scout | Transform、RouteMover、CommandReceiver、Visual | 验证快速移动和路线 |
| Carrier | Transform、WeightedMover、CommandReceiver、Visual | 验证不同运动约束 |
| Observer | Transform、StationaryMover、Behavior、Visual | 验证固定实体和触发事件 |

所有名称和参数为合成值。

### 阵营

- Blue：由用户下达指令；
- Red：由预设有限状态机产生仿真内部指令；
- Neutral：只表示目标区域和环境对象。

## 4. 主验收旅程

1. 新建一个 RouteMover 模型包并通过 Schema 校验。
2. 打开地图资产，添加道路、障碍和出生区。
3. 创建场景，引用地图和三个实体原型。
4. 部署 Blue/Red 两个阵营的多个实体。
5. 选择随机种子并生成 RunManifest。
6. 启动仿真，态势界面显示实体和仿真时间。
7. 用户选择 Blue 实体并下达设置目的地指令。
8. Command Gateway 返回 Accepted；事件进入仿真队列。
9. Mover 按仿真时间更新位置，产生状态增量。
10. Red Behavior 在预设条件下生成移动或停止指令。
11. 实体进入目标区或触发合成接触条件时，生成抽象 InteractionEvent。
12. 用户暂停、单步处理一个事件，再切换到倍速运行。
13. 场景达到结束条件，生成结果摘要。
14. 用户拖动时间轴查看指令、轨迹和关键事件。
15. 使用同一 RunManifest 重新运行，关键事件摘要一致。
16. 安装第二个 Mover 插件并替换一个实体，不修改内核。

## 5. 指令集合

第一版只允许通用仿真指令：

- `SET_DESTINATION`；
- `SET_ROUTE`；
- `STOP`；
- `RESUME`；
- `CHANGE_MODE`；
- `ASSIGN_SYNTHETIC_TASK`。

每条指令必须出现以下一种最终状态：Completed、Rejected、Expired 或 Cancelled。不得出现永远停留在 Executing 且无诊断信息的状态。

## 6. 场景结束条件

- 达到预设仿真时长；或
- 一方完成合成目标；或
- 控制人员主动停止；或
- 内核发现不可恢复的一致性错误并安全终止。

结束后必须生成：RunManifest、事件日志、状态快照索引、指标摘要和回放入口。

## 7. MVP 验收

| 能力 | 通过标准 |
| --- | --- |
| 模型复用 | 同一 Scout 模型在两个场景中使用，无源码复制 |
| 地图/场景分离 | 更换场景规则不修改地图资产 |
| 指令 | 每条指令具有完整状态和相关事件 |
| 运动 | 实体位置只由仿真时钟和 Mover 更新 |
| 显示 | UI 只消费快照和增量投影 |
| 时间 | 暂停不推进仿真时间；单步只处理定义的一个边界 |
| 复现 | 相同 Manifest 的关键事件和摘要一致 |
| 回放 | 无需重新运行即可查看完整态势变化 |
| 扩展 | 新增一个 Mover 不修改内核模块 |
| 安全 | 全部资产为合成数据，所有指令仅作用于沙盘 |

## 8. 第二参考场景

完成第一场景后必须创建结构不同的第二场景，例如“环形巡检演示”。它复用地图格式、实体组件、指令、事件和态势显示，只新增场景配置和一个插件。若必须修改核心，记录为架构缺口而不是直接复制实现。
