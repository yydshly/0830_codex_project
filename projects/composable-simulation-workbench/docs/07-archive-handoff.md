# 归档与恢复说明

## 1. 归档状态

- 状态：暂时归档（Paused）；
- 归档日期：2026-08-31；
- 当前阶段：开发前产品与架构研究完成，尚未进入运行时代码实现；
- 归档原则：保留全部决策和开放问题，不把草案描述为已经验证的产品能力。

暂时停止的原因不是技术不可行，而是当前没有需要立即交付的试点场景、实现团队和明确工期。继续开发会从需求研究转为持续的软件产品投入，因此在新需求出现前保持冻结更合理。

## 1.1 来源链

本探索从 [Anthropic FDE 面试指南深度研究](../../anthropic-fde-interview-guide-research/README.md)延伸而来。上游研究说明如何从客户业务结果、失败成本、权限边界和采用证据反推最小系统；本项目把这套方法应用于“仿真项目重复实现公共能力”的观察，形成产品 Charter、参考场景和架构基线。

两者需要保持边界：FDE 是一种端到端落地角色和方法，不等于仿真平台；可组合仿真工作台只是一个候选落地方向，不代表已经证明市场需求或完成软件实现。

## 2. 当前定稿理解

产品定位为一个面向完全合成、封闭环境的可组合实时仿真工作台。它提供模型、地图、场景、指令、时间、运动、态势、事件、指标和回放的公共能力，目标是让第二个场景主要通过配置和插件完成，而不是重新实现仿真内核。

产品不定位为：

- AFSIM、VR-Forces 或 STK 的直接替代品；
- 完整 RTS 游戏；
- 第一版即可用于现实决策的验证级系统；
- 真实设备、真实指挥系统或受限网络的控制软件。

更合适的实施策略是“核心自研、通用能力复用、专业系统后期适配”：自研时间、事件、指令、状态、运行清单和回放语义；复用渲染、地图、数据库、序列化和互操作协议实现。

## 5. 优先应用场景

恢复时优先从以下两个场景中选择一个作为真实试点：

1. 合成红蓝场景快速原型：验证地图、实体、指令、时间、运动、态势和回放闭环；
2. 态势/控制软件的合成数据联调：通过可重复实体状态、指令回执和异常事件验证界面与业务流程。

后续候选包括教学训练、路径/调度算法对比、批量实验，以及物流、应急、交通、园区巡检等非军事多主体仿真。现实验证级分析和分布式联合仿真需要新的 Charter、数据授权和 V&V 计划。

## 6. 恢复条件

满足以下任一业务条件时可以重新开启评审：

- 出现一个有明确用户、输入、输出和验收标准的试点场景；
- 需要为态势或控制软件提供确定性的合成数据源；
- 现有项目再次重复实现时间、指令、运动、态势或回放能力；
- 有人员和时间完成至少 Spike A，而不是只制作界面演示；
- 需要评估采购专业产品与自研平台的边界。

恢复前还应确认：产品负责人、实现负责人、预计投入、首个场景、目标实体规模、离线部署约束和是否存在外部接口。

## 7. 最短恢复路径

```text
确认试点用户和场景
→ 评审并冻结 Product Charter
→ 将参考场景改成可执行验收夹具
→ Spike A：确定性仿真内核
→ Spike B：指令闭环
→ Spike C：态势投影与回放
→ 根据证据决定是否进入 P0
→ 需要插件时再执行 Spike D
```

恢复后的第一个代码目标应是无完整编辑器的 Walking Skeleton：加载手写场景、运行两个阵营的合成实体、提交移动/停止指令、暂停/单步/倍速、记录事件并确定性重放。

## 8. 恢复验收门

继续投入完整产品前，至少应证明：

1. 同一 RunManifest 重复运行产生一致领域事件；
2. UI 与仿真权威状态隔离；
3. 每条指令具有确定终态和机器可读原因；
4. 回放不依赖重新执行仿真；
5. 第二个结构不同的场景无需修改核心契约；
6. 实测容量满足首个试点，而不是凭架构假设承诺规模。

若上述条件无法通过，应优先调整范围、采购现有产品或只保留专项仿真工具，不继续建设通用平台。
