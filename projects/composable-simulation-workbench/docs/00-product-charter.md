# Product Charter v0.1

## 1. 产品定义

可组合红蓝仿真工作台是一个面向合成、封闭环境的实时仿真产品。它为场景制作、仿真控制、态势观察和扩展开发提供统一工作台，使用户可以通过配置和插件完成双阵营多实体场景，而不是为每个项目重新实现模型、地图、时间、指令、显示与回放。

“类似经典 RTS”只描述第一视角体验：俯视地图、选择单位、下达指令、实时运动、阵营对抗和清晰反馈。产品不复制任何现有游戏的内容、资产、名称、规则或代码。

## 2. 北极星

> 一个不了解仿真内核的场景制作人员，可以通过模型、地图和场景资产，完成一场可运行、可控制、可观察、可回放的双阵营多实体仿真；第二个场景主要通过配置和插件完成，不修改平台核心。

## 3. 目标用户与工作

| 用户 | 核心工作 | 成功表现 |
| --- | --- | --- |
| 模型制作人员 | 定义实体、组件、参数和验证用例 | 模型可版本化、复用和独立验证 |
| 地图/场景制作人员 | 制作地图、部署阵营、目标和规则 | 不写内核代码即可形成可运行场景 |
| 仿真控制人员 | 启停、调速、下达仿真指令和干预预设事件 | 每条指令有状态、时序和审计 |
| 观察分析人员 | 查看态势、事件、轨迹、指标和回放 | 能回到任意关键时刻解释发生了什么 |
| 扩展开发人员 | 增加运动、行为、指标、显示图层或引擎适配 | 新扩展不要求修改核心模块 |

## 4. 核心业务结果

1. 缩短从需求到首个可运行场景的时间。
2. 提高模型、地图、场景模板和显示图层复用率。
3. 降低第二个项目的定制代码占比。
4. 让同一次运行可以重建、比较和回放。
5. 让平台升级具备基于参考场景的回归证据。

指标暂不承诺数值，在技术 Spike 后为以下项目建立基线和目标：

- Time to First Runnable Scenario；
- 第二场景的核心代码改动数；
- 模型和图层复用率；
- 相同 RunManifest 的关键事件一致率；
- 指令接受到状态反馈的延迟；
- 态势显示在目标实体规模下的刷新稳定性；
- 平台升级后参考场景回归通过率。

## 5. 产品支柱

### 5.1 可组合

实体由组件组成；地图与场景分离；场景引用版本化模型；运动、行为、指标和显示图层通过稳定扩展点安装。

### 5.2 可控制

所有外部输入先转为 SimulationCommand，经权限、Schema、前置条件和仿真时间检查后进入队列；不得直接修改内核状态。

### 5.3 可观察

状态变化产生标准事件；态势显示消费读模型，不读取或持有内核对象；关键事件可检索、解释和回放。

### 5.4 可复现

运行记录场景、模型、平台、随机种子、环境、参数和制品校验值。相同 RunManifest 必须生成一致的关键事件序列和结果摘要。

### 5.5 可分级保真

| 等级 | 定义 | 当前状态 |
| --- | --- | --- |
| L0 交互演示 | 指令、运动、事件和显示形成闭环 | Walking Skeleton |
| L1 合理行为 | 时间、路径、运动和规则符合常识且可复现 | MVP 目标 |
| L2 参数化模型 | 单位、范围、误差、适用域和校准数据明确 | 后续 |
| L3 验证级模型 | 有权威数据、V&V 报告和适用范围 | 独立专业项目 |

第一版不以界面真实感代替模型有效性，不将 L0/L1 结果宣传为现实分析结论。

## 6. MVP 范围

- 单机、离线优先；
- 一张 2D/2.5D 合成地图；
- 两个虚构阵营；
- 数十个合成实体，精确容量由 Spike 决定；
- 2–3 种通用 Mover；
- 模型、地图和场景资产的保存与加载；
- 仿真内部移动、停止、改变模式、分配合成任务等通用指令；
- 一个完全虚构的交互结果插件；
- 启动、暂停、恢复、单步、倍速和尽快运行；
- 地图、实体、轨迹、事件、指令和时间显示；
- 事件日志、快照、运行清单和完整回放；
- 一个新增 Mover 或 VisualizationLayer 的 SDK 示例。

## 7. 第一版非目标

- 基地建设、资源经济、科技树和完整游戏内容；
- 真实装备、真实环境、真实任务和真实规则；
- 高保真武器、传感器或效应模型；
- 与现实设备、控制系统或行动网络连接；
- 公网多人游戏和反作弊系统；
- 分布式联合仿真和跨安全域交换；
- 高精度空气动力学或通用物理求解器；
- 自由 LLM Agent 控制实体或修改仿真状态；
- 未经授权的第三方仿真引擎、代码、模型和数据适配。

## 8. 支持边界

所有指令、行为和交互只存在于合成沙盘。公开演示使用虚构名称、几何图形和通用参数。不存放过去项目中的源码、模型、配置、地图、日志、截图、需求或记忆性复刻内容。

## 9. Charter 冻结门槛

进入完整开发前，产品负责人、架构负责人和实现负责人必须共同确认：

1. 北极星和主旅程没有冲突；
2. 第一版保真度为 L1，而非专业验证级；
3. 一张地图、两个阵营和数十实体足以验证价值；
4. 指令只作用于仿真；
5. 第二场景复用是核心验收，而不是只完成一个 Demo；
6. 地图编辑器和模型编辑器先支持最小配置，不追求一次做完；
7. 技术栈在 Spike 后决定。
