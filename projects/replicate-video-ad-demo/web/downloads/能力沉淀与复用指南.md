# 能力沉淀与复用指南

## 长期定位

这个项目的长期意义不是保存一条 AirPods 案例，而是沉淀一套以后可以反复调用的“优秀视频结构迁移能力”。

遇到新的广告、发布片或产品表达需求时，不需要重新讨论“怎么参考优秀视频”这一基础问题，可以直接复用本项目已经验证过的能力链：

```text
优秀参考视频
→ 可追溯媒体证据
→ 广告表达机制
→ 目标产品生产架构
→ 分段生成与后期计划
→ 结构化验收
```

因此，这个库应该被视为：

- 一套参考视频分析方法；
- 一套新产品结构迁移规范；
- 一套视频生成前的约束协议；
- 一套商品事实与版权边界检查；
- 一套“有 Skill / 无 Skill”效果评估基线；
- 一个可继续增加真实案例的能力样板库。

它不是成片素材库，也不是通用的一键视频生成平台。

## 后续可以直接复用什么

| 能力资产 | 当前载体 | 后续用途 |
|---|---|---|
| 视频探测、抽帧、故事板、Manifest、音频准备 | 按《上游依赖与获取》准备的抽帧器与 `demo/run_extractor.ps1` | 为任何已授权本地参考视频建立可复核证据 |
| 观察事实与剧情功能分离 | Skill 方法与方法论文档 | 防止把主观解释直接当成原片事实 |
| Hook → Proof → Payoff 等功能级分析 | 当前真实案例与生产包 | 识别镜头在广告中的作用，而不是只描述画面 |
| 保留机制 / 替换元素 | 结构迁移方法 | 把参考片的优秀之处迁移到完全不同的产品 |
| observed / adaptation / placeholder | 商品主张控制 | 避免继承原广告宣称或让模型编造新参数 |
| 连续性锚点与分段生成计划 | 生产架构模板 | 降低人物、产品、服装、色彩和运动方向漂移 |
| Editing & Finishing Plan | 当前生产包 | 把生成镜头推进到可交付成片，而不止停留在 Prompt |
| 浏览器与离线验证 | `demo/verify_demo.py` 与 Web 验收记录 | 检查产物是否完整、页面是否可用、文档是否一致 |
| A/B 评估框架 | 评估模板 | 判断 Skill 是否真的减少返工、幻觉和成本 |

## 每个新任务必须重新提供什么

下面内容不能从当前案例直接继承：

| 必须重填 | 原因 |
|---|---|
| 新参考视频及其授权范围 | 参考作品和可使用范围发生变化 |
| 目标产品及真实核心能力 | 不同产品不能继承 Relay Arc 的虚构设定 |
| 用户、场景与沟通目标 | 决定应该迁移哪些机制、放弃哪些机制 |
| 产品外观与品牌资产 | 决定生成阶段的视觉条件和连续性锚点 |
| 可发布商品事实与法务口径 | 决定哪些主张可以进入后期文字 |
| 时长、比例、渠道和预算 | 六段、35 秒和 16:9 不是普适模板 |
| 视频模型及其能力边界 | 不同模型支持的参考图、首尾帧和单段时长不同 |
| 音乐、声音、字幕与交付规格 | 最终渠道和授权要求不同 |

一句话原则：**复用方法和模板，重新填写事实与创意决策。**

## 推荐复用方式

### 模式 A：作为新项目的起点

1. 复制 [`任务输入模板`](../templates/任务输入模板.md) 到新项目。
2. 填写参考片来源、目标产品事实、素材、渠道和预算。
3. 使用上游抽帧脚本建立证据。
4. 按 [`视频生产架构模板`](../templates/视频生产架构模板.md) 完成结构迁移。
5. 生成阶段使用“生产架构 + 产品事实 + 产品资产”，默认不再输入原片。
6. 使用 [`A-B评估模板`](../templates/A-B评估模板.md) 做结果评估。

### 模式 B：作为分析与交付规范

即使不运行本项目脚本，也可以把输入模板和生产架构模板交给其他 Agent、导演或内容团队，要求其按照相同栏目交付。这样可以统一不同团队的输出质量和审查口径。

### 模式 C：作为能力评估基线

对同一产品、同一模型和同一预算分别运行：

- 无约束方案：一句泛化参考指令；
- 有约束方案：本项目生产架构模板；

用相同指标盲评，持续记录哪些约束真正有效。库的价值应由稳定增益证明，而不是由单次样例是否漂亮证明。

## 新任务的标准输入与输出

### 最小输入

- 一个来源清晰、可用于分析的参考视频；
- 一个目标产品和明确的沟通目标；
- 产品核心能力的事实状态；
- 基本产品参考图或外观说明；
- 目标时长、比例和渠道。

### 标准输出

- Source Summary；
- 证据 Manifest 与故事板；
- Shot Timeline；
- 功能级机制与迁移决策；
- 商品事实账本；
- 连续性锚点；
- 全片创意与连续性总纲；
- 分段生成计划；
- 负面约束；
- Editing & Finishing Plan；
- 验收结果与 Handoff Note。

## 完成标准

一个新案例只有同时满足以下条件，才算复用了本库的完整能力：

1. 每个关键判断可以回到原片时间点或证据帧。
2. 观察事实和主观解释明确分开。
3. 能说明参考片中哪些机制值得保留，以及为什么适合目标产品。
4. 目标片拥有自己的用户问题、产品触发、行为结果和品牌收口。
5. 没有复制原片人物、品牌、造型、音乐、文案和具体镜头。
6. 核心功能、触发方式、使用条件和参数都有事实状态。
7. 生产架构脱离原片后仍能被视频模型或制作团队执行。
8. 生成计划包含跨段连续性锚点和首尾帧衔接。
9. 后期计划包含声音、文字、品牌、法务和导出。
10. 最终评价看结构完整度、真实性和可剪辑率，而不是“像不像原片”。

## 版本演进建议

后续每增加一个真实案例，都应记录：

- 参考片类型与目标产品类型；
- 成功迁移的机制；
- 放弃迁移的机制及原因；
- 视频模型、预算和生成参数；
- 连续性问题与返工次数；
- 商品主张错误；
- 可用镜头比例和最终剪辑时长；
- 无 Skill / 有 Skill 的对照结果。

案例数量增加后，可以进一步沉淀为按场景检索的模式库，例如：产品发布、功能证明、使用前后对比、运动表现、情绪品牌片和电商转化广告。但每个模式都必须有真实案例证据，不能只靠理论扩写。

## 当前成熟度

当前项目已经完成：

- 上游脚本固定快照；
- 合成基线案例；
- 真实热门广告案例；
- 三层能力模型；
- 新产品生产架构与原创概念分镜；
- 输入、交付和 A/B 评估模板；
- Web 展示与离线验证。

尚未完成的是调用视频生成 API 产出两组最终成片并进行统计评估。因此当前可以作为可靠的分析与生产规划参考，但还不能宣称已经证明对所有视频模型都有稳定增益。
