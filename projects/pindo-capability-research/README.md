## 项目摘要

Pindo 是一个在浏览器本地运行的**拼豆图纸转换工具**，不是生成式 AI。它把照片、插画或旧图纸转换成受品牌色板约束的像素网格，给出色号、理论用量和制作辅助。核心原理是缩图采样、RGB→Lab 色差匹配、限色、误差扩散、孤立色清理和网格检测。

| 问题 | 阶段结论 |
| --- | --- |
| 它能做什么 | 图片转拼豆图纸、8 套品牌色板匹配、三种采样模式、色号高亮、PNG 导出；Focus 与 PDF 有底层实现，但没有完整接入主流程。 |
| 适合谁 | 拼豆爱好者、亲子手工、工作坊和小规模定制商，尤其适合不希望把家庭照片上传云端的本地处理场景。 |
| 当前不足 | 自动结果仍需逐格编辑；12×12 实测曾误判为 13×13；倾斜图缺少可靠校正；屏幕色不等于实物色；依赖存在安全告警；上游固定提交没有明确许可证。 |
| 最值得补什么 | 优先补可编辑图纸、撤销与版本、库存约束、缺色替代、BOM/成本和制作进度闭环，而不是继续堆更多“AI 模式”。 |
| 对我们的意义 | 它证明了“目标图 → 有限元素目录 → 约束匹配 → BOM → 制作引导”可以成为跨材料的编排底座，后续可扩展到纽扣、花材、积木、灯光节点等。 |

本研究进一步提出了一个独立的情绪产品假设：把共同记忆写入灯，而不是只把图片做成手工作品。**Pindo One** 是私密单灯，**Pindo Nine** 是九窗共同记忆灯，**Pindo Constellation** 是空间化自由星群。三者共用记忆内容与隐私规则，但硬件拓扑不同。它们是本研究的产品扩展概念，**不是上游 Pindo 已经具备的能力，也不是在售硬件**。

阶段判断：原库研究与网页演示已完成，暂不继续深入。未来只有在出现真实用户访谈、可编辑图纸需求、实物色差测试条件或记忆灯 MVP 预算时再恢复。

## 什么是拼豆

“拼豆”不是豆子，也不是软件术语。它是一种像素手工：把一颗颗中间带孔的彩色塑料小圆珠摆在带钉底板上，组合成图案；摆完后盖上熨烫纸，用熨斗加热，使塑料珠边缘熔合；冷却后从底板取下，就得到一个像素风挂件、杯垫或摆件。

最小闭环只有四步：

1. 选择一张格子图纸。
2. 按格子里的颜色或色号，把相应塑料珠放到底板钉柱上。
3. 盖熨烫纸并加热，使珠子彼此粘合。
4. 冷却、取下并检查成品。

因此拼豆图纸类似十字绣图纸：每一格对应一颗实体材料，颜色不只是屏幕色，还要对应某个品牌可以买到的具体色号。儿童参与熨烫步骤时需要成人处理或全程监督。

## 研究问题

[`LunarXuan/Pindo`](https://github.com/LunarXuan/Pindo) 是否完成了“普通图片 → 品牌拼豆色号 → 用量与拼版 → 实际制作引导”的完整闭环？它依赖什么算法，实际能力边界和可扩展价值是什么？

成功标准：

- 能从源码解释图片如何变成一格一颗豆的图纸；
- 能区分图片生成、图纸识别、色号高亮和拼豆制作模式；
- 上游锁定依赖后的自动测试与生产构建可以通过；
- 研究页能让没有接触过拼豆的人通过交互演示理解核心概念；
- 明确许可证、依赖安全、识别鲁棒性和实物色差边界。

不在本次研究范围内：购买真实品牌拼豆、熨烫实体成品、测量材料批次色差、发布 Pindo 修改版或进行付费 API 调用。

## Pindo 实际做什么

| 用户输入 | Pindo 处理 | 用户得到 |
| --- | --- | --- |
| 照片、插画或像素图 | 缩成指定颗数，匹配品牌色表，限色和降噪 | 带网格、品牌色号和用量的图纸 |
| 有网格但无色号的图纸 | 检测网格线，读取每格主色，匹配品牌色号 | 补全色号和用量的图纸 |
| 无网格图纸 | 按用户输入宽高均匀切格，读取主色 | 可继续制作的近似图纸 |
| 已生成或识别的图纸 | 按色号高亮 | 制作时只显示某一种或几种色号 |
| 手动写入 `pindo-focus-data` 的图纸 | `/focus` 按颜色和四连通区域记录完成状态与用时 | 制作过程引导与进度；当前主页面尚未接通这条数据链路 |

它支持 README 声明的 8 套可用品牌色板、写实/主色/清晰三种创作模式、PNG 导出和 Android 打包。仓库存在 PDF 导出实现，可按默认 29×29 底板拆分页并加入校准框、色号和对齐标记，但固定提交的 `ExportPanel` 只接入了 PNG，因此 PDF 目前是“有底层代码、无界面入口”的能力。

## 原理

生成路径：

```text
图片加载与背景处理
→ 可选主体裁切、亮度/对比度/饱和度/锐化
→ 缩成“宽 × 高颗”的颜色矩阵
→ RGB 转 Lab，以简化 CIEDE2000 匹配品牌色号
→ 可选 Floyd–Steinberg 误差扩散
→ 保护明暗与高饱和关键色并限制总色数
→ 删除孤立小色块、执行多数滤波
→ 生成 colorId 矩阵、统计数量、拆分底板并导出
```

三种创作模式不是三套 AI 模型：

- 写实：在线性 RGB 空间对每格覆盖的原图区域取平均，保留渐变和细微色彩。
- 主色：选择每格区域内占比最大的颜色簇，减少混色和零碎色。
- 清晰：比较亮度差并保护深色轮廓，让低分辨率图更容易辨认。

识别路径同样是传统图像处理：先裁掉近似纯色外边距，再对横纵方向建立线条评分，寻找间距稳定的网格；找到网格后避开边框，在每格中心区域做加权主色采样；找不到网格时则按用户给定宽高等分。最后仍然通过色差映射到品牌色表。

所以 Pindo：

- 不是生成式 AI；
- 不需要服务器推理；
- 图纸识别不是 OCR，不会真正阅读图片中印刷的字母数字；
- 结果主要由采样策略、色差公式、品牌色表和清理规则决定。

## 方法

1. 在仓库忽略的 `.tmp/` 目录浅克隆上游 `main` 并记录完整提交号。
2. 检查 README、应用页面、图像引擎、色板加载、图纸识别、导出和 Focus 制作模式。

## 场景样例实测

全部输入均在本项目原创，实验固定到上游提交 `5b6c85c`。页面可在
[`web/index.html`](web/index.html) 的“目标场景样例”区交互查看；机器可读记录见
[`evidence/sample-cases.json`](evidence/sample-cases.json)。

### 场景 1：头像定制接单

小型定制商收到客户头像，希望当天给出拼豆方案。现实约束是 35×35、最多 16 色、4 块 29×29 底板内；当前可得到报价初稿，但五官和肤色仍需人工确认。

输入为 600×600 的原创人物插画，统一设置为 MARD、35×35 颗、最多 16 色、白色背景、无抖动：

| 模式 | 实际色数 | 总格数 | 用量最多的 5 个色号 | 观察 |
| --- | ---: | ---: | --- | --- |
| 写实 | 15 | 1,225 | M08×240、P18×154、B22×136、F01×109、H06×100 | 渐变过渡更连续，局部色号较分散 |
| 主色 | 15 | 1,225 | M08×218、F01×197、P18×158、B22×155、H16×148 | 大色块更集中，但没有自动减少总色数 |
| 清晰 | 15 | 1,225 | F01×209、M08×207、B22×154、H16×148、P18×121 | 深色头发、五官和衣服边界更稳定 |

这个样例最重要的结论不是“哪张最好”，而是模式需要按成品目标选择：肖像细节优先可从写实开始，小尺寸辨识度优先更适合清晰，采购颜色种类仍应另外调低“最多颜色”。

### 场景 2：亲子一小时挂件

家长与孩子希望周末一小时完成一个角色挂件。任务必须控制在 16×16、最多 8 色和单块底板内，减少换色和找豆的负担。

原创吉祥物使用清晰模式、16×16 颗、最多 8 色，实际输出 6 色、256 格，只需 1 块 29×29 底板。硬边和眼睛、嘴、身体轮廓仍能辨认；如果不把最多颜色从 16 主动降到 8，同一输入会产生 14 个近似色，采购和摆放负担明显上升。

### 场景 3：工作坊复刻旧图

工作坊老师需要把一张纸质旧图复刻成多人活动材料。原图已知为 12×12，拍照可能倾斜；只要尺寸仍有疑问，就不能直接批量备料。

正视输入明确包含 12×12 个格子，Pindo 显示“已自动识别网格”，但结果是 13×13、169 格。这说明算法把网格线或边界计算成了多一行/列，成功提示不能替代人工尺寸核对。

把同一张图旋转 9° 后，结果变为“已裁剪空白边，并按当前宽高颗数均匀切分”。手工填写 12×12 后可继续生成 144 格图纸，但格内采样已经混入倾斜网格线和背景，实际色数从正视图的 4 色变为 5 色。这是透视校正和鲁棒识别的明确扩展机会。

### 场景 4：大图分批续做

分多天制作大图的玩家，希望每次回来都能继续上次进度。当前只有手工注入的 12×12 夹具能演示连通区域完成，真实生成项目尚不能自然进入 Focus。

`/focus` 页面本身能显示计时、颜色列表、总进度，并按四连通区域批量标记：在手动注入的 12×12、144 格测试图中，点击连续背景区域一次就把 H18 的 98 颗全部标记完成，总进度变为 98/144（68%）。

但在固定提交中，主生成页没有 `pindo-focus-data` 写入逻辑，也没有进入 `/focus` 的按钮；正常生成图纸后直接访问该路由只会看到“没有图纸数据，请先生成图纸”。所以应把它判断为可运行但尚未完成产品集成的能力。

## 发现

### 已观察事实

- Pindo 是一个完整应用，不是提示词模板：它包含 Next.js 前端、Canvas 图像处理、色板数据、PNG/PDF 导出和 Capacitor Android 配置。
- 图片始终可以在浏览器本地处理；静态构建不要求业务服务器。
- 主页面实际编排了调整、裁切、三种缩图模式、色差匹配、限色和低分辨率清理。
- 图纸识别依赖网格几何与格内颜色，不依赖 OCR 或机器学习模型。
- Focus 页面支持按颜色、按四连通区域标记完成，显示总进度和计时；但固定提交中主生成页没有写入它依赖的 `pindo-focus-data`，也没有进入入口。
- PDF 导出器存在于源码，但固定提交的导出面板只接入 PNG。
- `ordered dithering` 在固定提交中仍是占位分支；界面实际暴露的是 Floyd–Steinberg 开关。
- 自动化测试覆盖 4 个核心模块，但没有覆盖颜色匹配、图纸识别、PNG/PDF 导出和完整浏览器旅程。

### 推断

- 它最适合拼豆爱好者、亲子手工、工作坊和小规模定制打样，而不是要求严格色彩管理的工业生产。
- 产品价值主要来自“图纸—色号—用量—制作”的闭环，而不是单个像素化算法。
- 本地处理特别适合儿童照片、家庭照片等不希望上传云端的内容。
- 商业化最自然的下一层是库存、缺色替代、材料成本和成套材料包，而不是先增加聊天机器人。

## 能力边界

| 看起来像 | 实际情况 |
| --- | --- |
| “AI 自动画拼豆图” | 传统采样、色差匹配和启发式清理 |
| “识别图纸上的色号” | 识别格子颜色后推断最接近的品牌色号，不读印刷文字 |
| “屏幕颜色就是实物颜色” | 色板 RGB 只是近似；相机、显示器、光源和生产批次都会产生偏差 |
| “数量统计就是采购量” | 统计是理论颗数；实际采购还需加入损耗、试熨和库存余量 |
| “公开仓库可以直接商用” | 当前没有明确许可证，商业再分发需要额外授权 |

## 局限与风险

- 本次没有用实物豆和标准光源验证品牌色号准确性。
- 当前只补充了正视和旋转 9° 两个原创网格输入；仍没有反光、透视、压缩噪声、水印和不规则网格的系统测试集。
- 已知 12×12 正视网格被报告为 13×13；自动识别成功状态仍需人工核对实际行列数。
- Focus 与 PDF 都存在底层实现但缺少主流程入口，不能按“用户已经可直接完成”来宣传。
- 13 项测试只能证明有限模块在既定样例上工作，不能代表端到端正确性。
- 依赖审计是时间敏感结果，而且同时包含生产、开发和间接依赖；不能把“26 项告警”简单解释为静态页面存在 26 条可远程利用漏洞，但也不能忽略。
- 默认最多约 200×200 颗；大量格子仍在主线程处理和渲染，低端移动设备可能卡顿。
- 无许可证是当前最明确的再利用阻碍。

## 可扩展方向

核心判断：当前 Pindo 只完成“自动初稿”，产品不应继续停留在增加缩图模式，而应补成“可修、可买、可做、可经营”的实体手工闭环。完整分析见 [`docs/product-opportunity-map.md`](docs/product-opportunity-map.md)。

先把“效果不好”拆成四类能力问题：

| 症状 | 应增加的核心能力 | 必须保留的人工控制 | 验证方式 |
| --- | --- | --- | --- |
| 人物不像、轮廓丢失 | 主体分割、多尺度采样、关键结构保护 | 原图叠加、五官和轮廓锁定 | 首次方案接受率、关键区域改动次数 |
| 颜色太碎、材料过多 | 库存约束色板优化 | 品牌、已有色、禁用色和预算 | 实际色数、缺料次数、材料成本 |
| 旧图网格识别错误 | 旋转/透视校正、网格候选与置信度 | 已知尺寸、可拖动网格边界 | 尺寸误判拦截率、校正时间 |
| 不满意只能重新生成 | Pattern JSON、逐格编辑、撤销和版本差异 | 锁定满意区域、终稿审批 | 重生成次数、终稿返工率 |

这些属于产品与技术扩展方案，不是固定提交已经实现的“优化后效果”。页面只使用当前真实输出作为问题证据，增强目标仍需实现后重新实测。

再向外扩一层，Pindo 还可以从“拼豆工具”演化为“万物拼装引擎”。真正可复用的不是圆形珠子，而是“目标图理解 → 元素目录 → 约束求解 → 制作交付”：

| 元素 | 它不是简单换贴图的原因 | 可能的产品出口 |
| --- | --- | --- |
| 花朵 | 花径、朝向、季节和萎蔫决定密度与替代方案 | 鲜花装置设计、采购清单、分区插花图 |
| 水果 | 切型、氧化、汁液、过敏原和冷链决定制作顺序 | 可食艺术编排、备料单与食品安全时间轴 |
| 叶片与种子 | 纹理方向、采集伦理、干燥色与脆裂决定复刻方式 | 生态拼贴课程、本地材料图谱 |
| 瓷砖与木片 | 厚度、灰缝、裁切、转角和承重决定能否施工 | 空间马赛克设计、建材 BOM 与放样图 |
| 灯光像素 | 地址、功耗、压降、散热和帧率让图案进入时间维度 | 动态像素编排、接线图与运行控制台 |
| 纽扣与布片 | 孔位、布料拉力、小件安全和拆洗决定可穿戴性 | 触觉拼贴、缝线路径与循环材料库 |

积木、糖果、贝壳、瓶盖、石子、纸片和金属片也可以作为后续插件。六种页面素材均为方向概念照，不是当前 Pindo 自动生成或已经实测的能力。

需要明确区分两种扩展：**创意扩展**回答“还能用什么、做什么作品”，**产品扩展**回答“服务谁、交付什么、谁来付费、如何增长”。材料扩展之上，Pindo 不应变成“每种材料做一个孤立工具”，而应形成共同底座：

```text
通用引擎（ElementSpec、可编辑图纸、约束、BOM）
→ 材料插件（豆豆、纽扣、瓶盖、积木、花材、灯光……）
→ 场景产品（创作、采购、教学、装置、空间）
→ 商业闭环（模板、材料包、报价、供应商、SDK）
```

产品扩展按客户与商业模式分成五条线：

| 产品线 | 客户与核心任务 | 客户购买的产品 | 付费与渠道 | 第一指标 / 门槛 |
| --- | --- | --- | --- | --- |
| Pindo Creator | 个人和小型卖家完成作品、减少返工缺料 | 可编辑图纸、库存、进度、项目库与专业导出 | 免费基础版 + Pro 订阅/买断；内容与创作者获客 | 周完成作品数、付费转化；先接通图纸、库存、Focus |
| Pindo Merchant | 材料商和定制商家完成报价、下单与履约 | 客户需求单、SKU/库存、报价、拣货分包与订单状态 | 商家订阅 + 交易服务费 + 材料毛利；品牌与商家渠道 | 报价转化、履约错误、毛利；先建立可信 BOM 与 SKU |
| Pindo Workshop | 学校、场馆和工作坊稳定交付并复用课程 | 课程模板、班级分工、批量备料、教师台与成果档案 | 席位/场地年费 + 按场活动包；机构销售与教培伙伴 | 课时完成、复用、续费；需要权限、隐私与安全规则 |
| Pindo Projects | 活动、空间和展陈团队按预算工期交付项目 | 报价审批、角色协作、施工变更、验收与维护 | 团队 SaaS + 项目许可 + 实施服务；行业直销与设计伙伴 | 报价周期、项目毛利、按期交付；需要专业规范与责任边界 |
| Pindo Platform | 品牌、供应商和开发者嵌入能力并发布规格 | API/SDK、ElementSpec 注册、插件/模板市场与结算治理 | API 用量 + 企业授权 + 认证 + 抽成；开发者与企业生态 | 活跃集成、API 用量、平台交易；必须先有稳定规格和真实交易 |

收入模式依次变厚：**工具收入 → 交易收入 → SaaS 收入 → 解决方案收入 → 平台收入**。推荐先同时验证 `Creator Pro` 和轻量 `Workshop`：两者共用编辑、BOM 与进度底座，一个验证个人付费，一个验证机构批量复用；Merchant、Projects 和 Platform 随后进入。

| 优先级 | 产品方向 | 用户得到 | 为什么现在做 |
| --- | --- | --- | --- |
| P0 | 图纸修复工作台 | 原图对照、逐格编辑、整图换色、撤销、版本和质量警告 | 这是库存、Focus、分享和商业化的共同数据基础 |
| P1 | 库存与成本规划 | 只用已有颜色生成、缺色替代、损耗、袋数、成本和采购单 | 解决“数量正确但买不到或太贵”，形成材料包入口 |
| P1 | 制作执行助手 | 从生成页进入 Focus，分板、区域进度、断点续做和 PDF | 现有代码已有部分能力，接通后才能真正完成作品 |
| P2 | 模板、分享与材料包 | 项目库、版本、remix、二维码、BOM、报价和订单导出 | 把一次性导出变成可复用、可交付的资产 |
| Later | 万物拼装引擎 | 花朵、水果、叶片、瓷砖、灯光、纽扣，以及可插拔元素目录 | 只有拼豆闭环验证后，扩材料才不会稀释产品焦点 |

如果继续向“与日常生活息息相关的情绪价值产品”扩展，核心也不必是手工。更合适的产品链是：

```text
照片 / 心情 / 关系 / 习惯 / 旧物
→ 色彩 / 图案 / 触感 / 光 / 材料构图
→ 日常成品、模块化物件或定制服务
→ 记录、陪伴、安抚、表达与保存记忆
```

研究页把方向整理为四组八款产品：

| 情绪任务 | 产品 | 主要交付与价值 |
| --- | --- | --- |
| 自我与仪式 | 情绪日历、成长拼图 | 用桌面成品和每日一块的轻操作，让心情与习惯变得可见 |
| 关系与陪伴 | 情绪氛围灯、关系留言板 | 用柔和光色与共享图案，让异地或家庭关系保持低打扰互动 |
| 安抚与表达 | 触觉减压物、情绪徽章与挂件 | 用触感、重量和可佩戴符号帮助调节状态、表达边界 |
| 记忆与再生 | 记忆相框、记忆再生产品 | 把照片、旧衣和纽扣做成可摆放、可赠送、可继续陪伴的成品 |

但这些方向仍只是机会假设。新的需求筛选把“市场已发生的购买”“Pindo 的形式假设”和“付费验证”分开，形成三个可用产品目标：

| 优先级 | 产品目标 | 真实用户任务 | MVP 与验证 |
| --- | --- | --- | --- |
| P0 | 记忆马赛克礼物 | 有收礼人、照片和明确日期，但不想再送模板化照片周边 | 三版预览 → 订金 → 精修 → 成品/材料包；先拿到 20 个非熟人付费单 |
| P1 | 旧物记忆再生 | 旧衣舍不得丢、长期占空间，并在搬家、毕业或纪念时必须处理 | 先做 10 个礼宾式服务单，不先开发平台 |
| P1 | 双人共同拼图 | 异地双方想每天确认彼此，但不想把联系变成聊天打卡 | 先做 30 对用户的双人网页，验证 14 天参与和最终实体购买 |

P0 选择记忆马赛克礼物，是因为个性化礼物已有替代购买和明确期限，也最接近 Pindo 当前图片转图案能力。类目证据只证明有人在解决这类问题，不证明用户会购买 Pindo；页面中的验证比例均是建议测试门槛，不是现有业绩。

其中“双人共同拼图”进一步形成了一个可写入的 **记忆灯产品族**。相遇、日常、感谢、支持、和好、成长、想念、约定和未来现在是一组关系内容池，不再与九个固定硬件一一绑定；每段内容都可写入情绪柔光、两个人的名字、双人照片、有意义的物品或一句短话。

| 氛围形态 | 灯窗数量 | 情绪距离与适合空间 | 显影节奏 | 产品角色 |
| --- | --- | --- | --- | --- |
| Pindo One · 一盏私语 | 固定 1 个灯窗；记忆数量独立 | 一个人被安静看见；床头、书桌与纪念角 | 一次只显出一段人物或物品，8–20 秒随机更换且不连续重复 | 入门款、礼物款与最低复杂度 MVP |
| Pindo Nine · 九盏共鸣 | 固定 3×3；九窗始终保持基础光 | 九段记忆共同在场；客厅、共享卧室与玄关 | 每轮错峰随机显影 1–3 个已写入灯窗，再共同退回柔光 | 家庭核心款与品牌标志形态 |
| Pindo Constellation · 自由星群 | 3–24 个独立节点，优先提供 5、9、15 三种预设 | 记忆延展成空间；电视墙、楼梯墙、酒店与展陈 | 约 20%–40% 节点稀疏显影，内容沿星群缓慢游走 | 高端定制、空间装置与 B2B 产品 |

研究页把三张 `memory-atmosphere-*.webp` 写实效果图同时放在产品族入口中。三张卡本身是可点击、可用方向键与 Home/End 切换的语义标签页；选中后只更新灯窗规则、内容节奏、适合空间与产品角色，不改写记忆、循环偏好或演示计时。这样读者可以直接比较三种氛围，而不会把它们误解成低、中、高配。

Nine 的自动展示也从“全局只显影当前一颗”扩展为更接近真实灯阵的错峰光场：九个灯窗同时保留基础光，每轮从已写入内容中临时随机选择 1–3 窗显出照片、名字、纪念物或短句，柔光阶段再一起收回。临时选择不改变编辑选中态、不写入 `localStorage`，随机队列仍避免连续重复；用户可选择 5、8、15 秒节奏，并随时暂停或单步查看。

为了不要求读者先写数据，页面保留独立的 30 秒展演。展演只使用内存中的临时示例，循环执行“1–3 窗显影 → 九窗柔光 → 下一组随机内容”，不会修改浏览器里的真实记录、未提交表单或循环偏好；`?demo=emotion` 可直接打开该效果，结束后恢复进入前的状态。

三种氛围共享内容引擎，但不能假装共享同一套硬件。One 是单显示面与一个磨砂柔光窗；Nine 可用一块旧平板或共用 LCD/OLED 配 3×3 遮光格栅，不需要九块独立小屏；Constellation 则需要 3–24 个独立可寻址节点、供电与通信轨道。当前网页原型可真实写入、覆盖、清空和本地保存九段关系内容，图片只在浏览器内压缩预览，不上传。

在八款单品之上，研究页继续整理成十条生活产品线：

| 产品线 | 主要价值 | 主要交付 |
| --- | --- | --- |
| Pindo Ritual | 完成晨起、归家和睡前的状态切换 | 情绪日历、心情钟、睡眠仪式灯 + 主题内容 |
| Pindo Together | 让家庭与异地关系保持低打扰陪伴 | 九豆记忆灯、共同画布与触碰灯 + 家庭账户 |
| Pindo Voice | 保存一个人的声音与说故事方式 | 声音记忆盒、家族故事书 + 定制整理服务 |
| Pindo Scent | 用气味恢复场景、季节与人物记忆 | 气味设备 + 场景胶囊与订阅 |
| Pindo Kids | 降低亲子情绪对话门槛 | 情绪认知板、睡前表达盒 + 年龄内容包 |
| Pindo Pet | 建立离家、远程回应和归家的稳定仪式 | 宠物陪伴设备 + 影像服务 |
| Pindo Moments | 让多人共同完成并带走一次人生仪式 | 活动装置、共同记忆墙与纪念品 |
| Pindo Gift | 降低私人礼物定制的选择与设计成本 | 在线方案生成 + 柔性定制礼盒 |
| Pindo Spaces | 让酒店、疗愈与商业空间根据人和时刻回应 | 空间装置 + 内容与维护服务 |
| Pindo Studio | 让创作者把数字图案转成可制造、可销售的产品 | 专业编辑器、规格库、样品包与主题市场 |

十条线现在只作为机会库存：先用 `Memory Gift` 验证真实成交，再用 `Memory Reuse` 的人工服务和 `Together` 的无硬件网页验证复杂需求；Ritual、联网硬件、Scent、Spaces 与 Studio 均应后置。十条线共用生活输入、情绪转译和产品生成能力，但不等于十条都已证明存在需求。

AI 适合成为 P0 的辅助层：主体分割、五官保护、背景简化和低分辨率语义提示。它不应替代确定的品牌色号、格子数量、库存约束和可撤销编辑。

## 对本研究仓库的意义

当前 Research Lab 已经研究了“提示词如何生成视频”和“如何把视频拆成可复刻信息”。Pindo 提供了另一条更接近实体交付的链路：

```text
原创角色或 AI 概念图
→ Pindo 转为拼豆图纸
→ 色号、颗数、底板与制作步骤
→ 亲子手工作品或材料包
```

因此它适合成为“数字创意如何落到实体手工”的基线项目。它还提供一个很好的对照：不是每个视觉产品都需要大模型；在输入、材料约束和交付格式明确时，传统图像算法加完整工作流也能产生直接价值。
