# 展示页设计契约

## Contract

- Entry mode：Revision-led；原始页面为 Brief-led。
- Request revision：R10；用户要求先模拟制作完整样例、直接生成相关素材并展示，因此在 R9 多端交付包上补充同一对 AI 虚构成年人的三幕故事素材，并重渲染请帖、16:9 大屏和 4:5 迎宾海报。
- Target user and context：希望先看到完整效果、再向新人确认资料的亲友策划者；页面也是婚庆服务商演示“信息收集—预览—多端交付—宾客反馈”闭环的本地样板。
- Desired first impression：先明确看到“AI 虚构人物、模拟资料、不可直接发布”，随后能看到同一素材系统怎样进入请帖、大屏、迎宾和回执产品。
- Visual ambition：Editorial。
- Experience architecture：Editorial Flow。
- Visual constraints：婚礼案例采用克制的朱红、金箔、暖砂岩与纸纹层次；以“张／董”真实笔画、两条红线和同心圆作为叙事锚点；延安只作为地点文字与抽象山形轮廓，不虚构地标、历史或字源；不自动播放声音。
- Information constraints：保留 R8 真实信息和边界，新增资料一律带 `SIMULATION／演示资料` 标识；模拟新娘全名、时间、场地、地址、联系方式、着装色、相识时间线和 AI 图片不得与用户提供事实混合；所有图片必须显示 `AI SIMULATED`，不得称为张帅、董小姐本人照片。
- Operation constraints：支持模拟请帖故事切换、真实横版视频播放、迎宾海报下载、项目 JSON 下载和本地 RSVP（姓名、是否出席、人数、祝福）；提交只更新当前浏览器，不发送、不保存；所有操作可键盘访问。
- State constraints：七条主视频分别支持正常播放与不可加载时的文字回退，同一时刻只播放一条；RSVP 有默认、校验错误、参加／不参加、成功和重置状态；模拟照片缺失时仍显示可读占位；reduced-motion 保留全部资料并关闭非必要切换动效。
- Environment constraints：原生 HTML、CSS、JavaScript；GitHub Pages 静态托管；桌面 1440px、平板 768px、手机 390px。
- Primary journey：进入婚礼案例 → 看见模拟／AI 身份声明 → 浏览三张连续故事图片的动态请帖 → 播放照片版 16:9 大屏片 → 查看并下载照片版 4:5 迎宾海报 → 浏览生成策略和多端复用结论 → 下载源图与完整样例清单 → 理解哪些资料必须由新人确认。
- User-defined phases：用户先授权模拟婚礼信息，再要求直接生成相关素材并完成一次样例的完整探索；本轮把 R9 抽象占位升级为一致人物素材链。
- Required artifacts：R9 全部产物、三张 AI 虚构人物源图与 WebP、媒体政策和交付清单、照片版 `WeddingScreen` MP4／海报、照片版迎宾海报、网页素材探索区、更新后的 README、设计契约、浏览器验收和自动检查。
- Autonomy authorization：用户明确要求由我们模拟信息并制作，授权在本地使用清晰标注的虚构资料、占位画面与可逆交互完成演示，不需要二次确认。
- User-decision boundary：不把模拟资料冒充真实；只生成完全虚构的成年人视觉，不使用真人照片或真实身份参考；不提交 RSVP 到服务器，不替用户发布、发送邀请或接入付费服务；任何正式交付都必须替换模拟信息并获得新人确认。
- Observable completion criteria：R9 既有要求继续通过；三张源图和优化图可读且人物／服装／色彩连续；网页、JSON、视频、海报均明确 AI 模拟身份；照片版横屏为 1920×1080、25 秒、H.264＋AAC；迎宾图为 1080×1350；源图、成片、海报与样例清单均可下载；1440／390、reduced-motion、图片错误回退、类型、媒体和仓库检查通过。

## Design direction

| Decision | Chosen direction | Observable constraint | Acceptance criterion |
| --- | --- | --- | --- |
| 信息层级 | 视频演示第一，判断与解释第二 | 首屏只保留一个主标题、一个结论和视频 | 首次扫描能说出“这是实际成片”和“当前不是通用生成器” |
| 字体 | 系统中文无衬线为正文，大字号高字重作标题 | 正文行长不超过约 72 字符 | 桌面和手机均无需放大阅读 |
| 色彩 | 黑板绿为背景、粉笔白为正文、黄色为能力强调、红色为边界提示 | 强调不只依赖颜色，均配文字标签 | 信息类别在单色环境仍可分辨 |
| 材质与深度 | 细边框、轻微粉笔颗粒感、少量层级阴影 | 不使用高成本 canvas/WebGL | 内容在禁用装饰后仍完整 |
| 响应式 | 桌面双栏首屏，窄屏单栏；卡片自动换列 | 390px 无截断、视频完整可控 | 三个目标宽度均无横向滚动 |
| 交互 | 原生视频、锚点导航、少量展开说明 | 不依赖 hover 才能获取信息 | 键盘可以到达所有操作元素 |
| 动效 | 仅使用简短进入/悬停反馈 | reduced-motion 下关闭非必要动效 | 偏好开启时没有持续动画 |
| 婚礼案例构图 | 左侧项目说明与分镜控制，右侧持续可见的婚礼舞台；窄屏按“舞台—控制—成片”阅读 | 桌面舞台为第一焦点，手机不把操作藏进抽屉 | 首次扫描能读出新人、日期、地点，并能找到播放和比例切换 |
| 婚礼案例色彩 | 朱红用于礼仪与相遇，金色用于姓名和日期，暖砂岩用于延安地点线索 | 关键信息同时使用文字与层级，不只靠颜色 | 禁用纹理和动画后仍能完整理解五幕故事 |
| 婚礼案例动效 | 笔画出现、红线相遇、同心圆与定格依次承担叙事 | 自动播放可暂停；单幕可直接访问 | reduced-motion 下立即展示完整静态定格，不隐藏文案 |
| 模拟资料语义 | 橙金 `SIMULATION` 标签与“正式使用前替换”文字同时出现 | 模拟状态不只依赖颜色，视频、海报、页面和导出均重复 | 首次扫描和每个下载入口均不会把虚构资料误认成真实邀请 |
| 完整请帖构图 | 大屏成片为主视觉，照片位／时间线为故事，RSVP 为明确次级操作 | 氛围占位不冒充真人照片，表单不遮挡媒体 | 桌面先看成片与请帖，手机按请帖—成片—海报—RSVP 顺序阅读 |
| RSVP 反馈 | 原生字段、行内错误、本地成功卡和重置 | 不出现“已发送给新人”等外部承诺 | 错误可恢复，成功明确写明“仅本页模拟，未发送或保存” |
| AI 人物连续性 | 身份锚点、同行、约定三幕复用同一人物、暖白服装与酒红色彩 | 不使用真人身份参考，不承诺精确身份复刻 | 三张源图和网页图可见，后两张基于前图约束，均有 AI 标签 |
| 素材探索构图 | 三张故事图为主，生成策略／多端消费／边界／产品结论为辅 | 桌面三列、手机单列，下载入口不依赖 hover | 1440×1100 与 390×844 无溢出，图片加载失败显示可读占位 |
