## 一句话结论

这个库的核心价值不是“给一张图加滤镜”，也不是“从合照无损抠出人物”，而是把肖像制作中的诊断、布光、身份与关系保持、画幅适配、质量门和失败重试组织为一套可复用的 Agent Skill。我们的工作台进一步把这些规则变成可操作、可检查、可导出的生产任务。

| 问题 | 结论 |
| --- | --- |
| 它能做什么 | 规划伦勃朗光肖像、多人共享光向或分别生成、个人品牌多画幅套图、宠物/编辑/系列化任务和人工 QA。 |
| 它不能独立做什么 | 不自带人物检测、分割、像素渲染、自动身份相似度或服务端存储；这些属于宿主模型和我们的系统。 |
| 对我们的意义 | 可作为模型无关的肖像生产中间层，让任务可回放、规则可版本化、失败可拒收、模型可替换。 |
| 可扩展方向 | 接入真实检测与生成适配器、局部修复、自动指标与回归集，再扩展到批量任务、模板、授权、隐私、成本和 SLA。 |
| 适用场景 | 家庭多人肖像、个人品牌套图、宠物纪念、编辑出版、摄影预演、团队标准、系列肖像、模型回归和垂直 Skill 模板。 |

## 目标

把 [`okooo5km/rembrandt-portrait-lighting`](https://github.com/okooo5km/rembrandt-portrait-lighting) 从一套文字型 Agent Skill，转译为用户既能操作、又能完整复盘研究证据和系统边界的多模式工作台。revision 2 不再把探索过程压缩进产品界面，而是提供三种互补视图：

1. **产品模式**：保留输入 → 计划 → 规则 → 质检 → 交付的真实闭环。
2. **探索模式**：完整呈现 8 个研究阶段、人物/宠物/多人证据、9 个使用场景和 7 个产品方向。
3. **架构模式**：明确 Skill、宿主图像模型和我们系统的责任，并让当前任务包随产品选择实时更新。

产品模式聚焦两条已有真实证据支持的路径：

1. 家庭肖像：保留多人同画面，或为每位成员分别规划独立肖像。
2. 个人品牌：从同一人物身份锁，规划 `1:1`、`4:5`、`3:4` 与 `16:9` 多画幅交付。

这个项目不会把底层生成模型的像素渲染能力伪装成仓库能力。仓库在工作台中的责任是：诊断主体几何、选择布光分支、锁定身份与关系、约束画幅、定义失败项和定向重试。检测、分割、生成、自动相似度与持久化仍是需要我们补齐的系统。

## MVP 真实边界

- 内置案例使用研究项目中已生成并保存的真实输入与输出，不新增模型生成结果。
- 本地上传使用浏览器 `FileReader` 完成真实预览，但静态 MVP 不声称自动检测人物，也不上传或保存文件。
- 工作台会按选择编译结构化任务说明、Skill 规则和 QA 检查项，并能下载为 JSON。
- 内置家庭案例的主体卡来自预先记录的 fixture，不是运行时视觉检测结果。
- “分别制作”代表为每个主体建立独立生成任务，不是从原图无损抠出像素。

## 已实现的产品闭环

- 家庭保留同画面：1 个任务、共享 image-space 主光向量、4:3 真实候选与 5 项 QA。
- 家庭分别制作：2 个独立生成任务、各自主体锁、2 张真实候选；任务 JSON 明确写入“不是无损提取”。
- 个人品牌套图：1 个身份锁、`1:1 / 4:5 / 3:4 / 16:9` 四个独立交付面、拒收重试证据与人工审批。
- 本地上传：真实 `FileReader` 预览；候选区保持空状态；导出的 JSON 把检测、生成和自动 QA 标为 `pending`。
- 交付：可见 JSON、复制回退和带 `download` 文件名的持续 Blob 下载链接。

## 完整探索信息

探索模式保留了从“仓库是什么”到“产品如何落地”的全部过程，而不是只展示最终结论：

1. 判断仓库是摄影工作流与质量约束 Skill，不是模型或推理 SDK。
2. 核对上游家庭多人证据与许可边界。
3. 用同源、同编辑器、各一次生成的黑色长毛犬 A/B 观察 Skill 的规则增量。
4. 用人物三分之四签名光压力测试证明：背景与完成度可改善，但闭环阴影仍可能失败；一次定向重试也可被规则正确拒收。
5. 验证 `1:1 / 4:5 / 3:4 / 16:9` 四个独立用途画幅，以及多人同画面共享光向。
6. 把能力扩展为 9 个真实场景：家庭、品牌、宠物、编辑、摄影预演、团队标准、系列肖像、模型回归与垂直 Skill 模板。
7. 推导 7 个产品方向，并区分“可演示 / 方法可用 / 需系统”。
8. 将规则编译、人工 QA 与任务 JSON 做成当前可运行工作台。

图像型场景只使用上游或相邻研究项目中已保存、可追溯的真实资产；过程型场景展示真实诊断、检查表、失败重试或执行配置，不用概念图冒充仓库能力。

## 架构与扩展路线

架构模式把完整链路拆为检测/分割 → Skill 诊断/锁定 → 宿主模型生成 → 规则与自动指标质检 → 审批/交付。扩展路线分为三层：

- H1 可靠适配：结构化参数、真实模型适配器、局部修复和版本记录。
- H2 可测量管线：检测、身份/关键点、背景质量、成本与回归数据。
- H3 产品系统：账号、任务、批量、模板、授权、隐私、删除与 SLA。

## 验证

```powershell
python projects/portrait-workbench-mvp/demo/verify_workbench.py
node --check projects/portrait-workbench-mvp/web/app.js
```

离线验证会先依据随项目提交的 SHA-256 台账确认 16 个网页证据资产未漂移；当相邻研究项目存在时，还会逐字节比对原研究资产。它同时检查两条 fixture、家庭两分支、品牌四画幅、三模式、8 阶段、9 场景、7 产品方向、动态架构包、规则来源、QA、上传/模型边界与响应式/降级标记。

浏览器验收覆盖 `1440×900`、`768×1024` 和 `390×844`；三模式切换、8 阶段键盘导航、场景过滤、品牌到架构包同步、产品交付闭环、亮暗主题、reduced-motion、脚本失败回退与 axe-core `4.13.0` 均已检查。自动化浏览器未能捕获本地 Blob 下载到磁盘，但链接的 `blob:` URL、`download` 文件名和 JSON 内容已确认；需在交互式 Chrome 或接入服务端导出端点后复测实际落盘。
