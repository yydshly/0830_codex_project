# 设计契约与覆盖清单

## 设计契约

- Entry mode：Revision-led holistic information and interaction refinement
- Request revision：2
- Target user and context：需要把一张家庭照或人物照转成可审阅肖像任务的内容创作者、家庭用户或视觉运营人员；当前通过本地静态原型理解能力边界。
- Desired first impression：这是一个既能完成真实任务、又能完整复盘研究证据与系统边界的多视图知识工作台；不是营销落地页，也不是“一键 AI 魔法”。
- Visual ambition：Editorial
- Experience architecture：Hybrid Workspace
- Scene base：HTML/CSS 图片舞台；源图、主体计划、候选结果和 QA 状态共享同一工作区。
- Scene persistence：桌面和平板中素材舞台持续可见；进入 QA 时同区域切换到候选证据。手机端按文档顺序排列，但当前步骤、素材和底部主操作持续可见。
- Foreground control model：顶部模式与主题控制；左侧素材/主体；中间证据舞台；右侧步骤和规则；无模态主流程。
- State-to-scene mapping：fixture 可用、上传预览、家庭保留、家庭分别、品牌多画幅、QA 待审、批准、拒绝、导出成功、fixture 加载失败。
- Mobile transformation：三栏工作区变为单列；步骤条横向可滚动；主操作使用正常文档流，不用遮挡内容的固定浮层。
- Fallback：无 JavaScript 时仍显示产品边界、两条流程、规则来源与真实效果证据；增强交互、上传预览和 JSON 导出不可用时明确说明。
- Visual constraints：温暖纸白/深墨双主题；一个铜金强调色只承担选中、焦点和主操作；图片保持原比例；不使用与任务无关的玻璃拟态、连续动画或大面积炫光。
- Information constraints：不遗漏 revision 1 之前的探索链路；产品模式保持精简闭环，探索模式完整呈现研究问题、控制方法、A/B、失败重试、九场景与七方向，架构模式区分 Skill、宿主模型与我们系统；不把预标注主体称为实时检测。
- Operation constraints：纯 HTML/CSS/JS、无外部依赖、无后端、无登录、无远程模型调用；上传文件只留在当前浏览器内存；能够复制或下载结构化任务 JSON。
- State constraints：家庭 fixture 支持保留多人/分别制作；品牌 fixture 支持四种画幅；QA 显示逐项通过、部分通过或拒绝并允许批准/拒绝；上传态只能生成“待检测/待生成”的计划，不能显示伪造结果。
- Environment constraints：本地 `python -m http.server`；Chrome/Chromium；桌面 1440×900、平板 768×1024、手机 390×844；简体中文；亮/暗双主题；键盘和 reduced-motion。
- Primary journey：在产品 / 探索 / 架构三种模式间切换 → 产品模式完成原有任务闭环 → 探索模式按时间线核对研究问题、方法、证据、结论与边界 → 架构模式结合当前 fixture 查看三方责任、任务包和产品路线。
- User-defined phases：保留已有产品闭环；补全全部探索过程；用不同模式降低信息冲突；优化阅读层级；保留真实样例与诚实边界。
- Required artifacts：可运行三模式网页、原有真实样例资产、新增人物/宠物 A/B 证据、探索时间线、九场景实验室、七产品方向、架构责任图、实时任务包、验证器、README、revision 2 设计契约、浏览器验收与交接记录、研究中心索引。
- Autonomy authorization：用户于 2026-08-30 明确要求“不要遗漏我们的探索过程信息，补全并更优化”，随后补充“用不同的模式展示”；授权在当前子项目内完成可逆的多模式信息架构、页面、文档和本地验证工作。
- User-decision boundary：接入真实检测/分割模型、调用外部图像生成服务、上传用户文件到服务器、引入账号/数据库、商业使用上游内容或处理真实肖像均需要新的产品与授权决定。
- Observable completion criteria：三种模式均可键盘访问且状态清楚；产品模式原闭环不回归；探索模式至少完整呈现 8 个研究阶段、3 组真实证据、9 个使用场景和 7 个产品方向；架构模式显示五步责任链、能力边界、当前任务包与三阶段路线；无 JavaScript 时所有关键研究信息顺序可读；桌面/平板/390px 无横向溢出；亮暗主题、失败回退和 reduced-motion 可用；自动检查与研究中心同步通过。

## Hybrid Workspace 分工

| 区域 | 属于持续素材舞台的动作 | 属于细节流的动作 |
| --- | --- | --- |
| 素材 | 选择 fixture、上传预览、查看预标注主体 | 阅读数据处理边界 |
| 计划 | 切换家庭/品牌、保留/分别、选择主体 | 查看 Skill 诊断理由 |
| 输出 | 比较真实候选、切换画幅 | 阅读 QA 项、批准/拒绝 |
| 交付 | 查看当前状态 | 复制/下载任务 JSON |

## Brief-led 设计方向

| 决策 | 方向 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| 构图 | 桌面为素材、舞台、决策三栏；舞台是视觉锚点 | 首屏不堆叠解释卡，当前任务和图片先于长说明 | 1440px 下无需滚动即可看见当前素材、路径与主操作 |
| 信息层级 | 当前步骤、当前证据、下一动作三者最强 | 所有能力声明旁边都有“Skill / 我们补齐 / 边界” | 首次扫描能区分规则能力与生成系统 |
| 字体 | 系统中文无衬线负责操作，衬线只用于大标题/样例标签 | 控件字号不低于 14px，正文行长受限 | 390px 不出现不可读缩放或标签截断 |
| 色彩 | 纸白与深墨双主题，铜金为唯一主强调 | 通过/部分/拒绝另用语义色并配文字 | 不依赖颜色单独表达状态，焦点轮廓可见 |
| 材质与深度 | 细边框、轻阴影、图片底板说明容器关系 | 不使用重玻璃、高模糊或装饰性光效 | 当前面板与非当前面板层级明确 |
| 密度 | 每步只显示当下决策，完整规则放在可展开区域 | 主路径不被长提示词淹没 | 从 fixture 到 QA 最多七个可见步骤 |
| 动效 | 仅用于状态切换和反馈，200ms 以内 | reduced-motion 下取消位移与平滑滚动 | 信息不依赖动画才出现 |
