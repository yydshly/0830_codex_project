# 04｜面试能力矩阵与四周准备路线

本章把页面中的面试主题转换成可执行准备计划。由于 Anthropic 没有公开统一 FDE 面试循环，这里训练的是稳定能力，不是预测原题。

## 1. 先建立个人证据表

每项能力至少准备一个真实证据。没有证据的能力优先通过实践项目补齐，不要用术语包装空白。

| 能力 | 需要证明 | 最佳证据 | 自评 0–3 |
| --- | --- | --- | --- |
| 生产编码 | 能构建可靠组件 | 代码、测试、事故处理、规模数据 |  |
| LLM/Agent | 不只是 Prompt Demo | 工具、上下文、Evals、轨迹调试 |  |
| 企业集成 | 能处理真实约束 | IAM、API、数据边界、审计 |  |
| 客户发现 | 能把模糊问题收窄 | 发现过程、取舍、Pilot 定义 |  |
| 安全可靠性 | 能限制高风险行为 | 审批、最小权限、回滚、威胁模型 |  |
| 业务结果 | 不只交付功能 | 时间、成本、质量、采用变化 |  |
| 跨职能 | 能处理分歧 | 与产品、安全、法务或客户协作 |  |
| Anthropic 动机 | 理解使命和岗位 | 真实、具体、与经历相连的理由 |  |

评分建议：0=无经验；1=知道概念；2=做过但证据较弱；3=有生产结果和深入反思。

## 2. 可能环节与准备目标

| 环节 | 主要信号 | 应准备的材料 | 确定性 |
| --- | --- | --- | --- |
| Recruiter | 动机、定位、物流、混合角色匹配 | 90 秒介绍、Why FDE、最佳部署案例、问题清单 | 常见但细节未知 |
| Coding | 实用编码、边界、测试、沟通 | API/JSON/重试/权限/解析题的限时练习 | 岗位需要，形式未知 |
| Applied AI | Agent 架构、工具、上下文、Evals | 一个端到端系统及失败复盘 | 高度匹配岗位 |
| System Design | 企业架构、安全、运营与采用 | 六区块设计框架和多个行业案例 | 高度匹配岗位 |
| Customer Discovery | 问题发现、范围和利益相关者 | 真实发现故事与模拟 Case | 合理推测 |
| Values/Safety | 判断、诚信、使命 | 安全权衡故事和真实观点 | 合理推测 |
| Behavioral | 主动性、合作、模糊性 | 6–8 个可复用 STAR 故事 | 常见但形式未知 |

进入正式流程后，向 Recruiter 核实，而不是依赖本表。

## 3. Recruiter 准备

### 90 秒自我介绍

结构：

1. 当前专业身份和最相关年限；
2. 一个最强的生产/客户 AI 案例；
3. 自己在案例中亲自承担的工程和发现工作；
4. 为什么这些经历自然导向 Anthropic FDE。

### Why FDE

强回答需要说明你为什么喜欢这个角色的“组合”，而不是只说喜欢 AI：

- 喜欢把模糊问题转成工作系统；
- 愿意同时面对代码、客户、权限和采用；
- 有进入陌生环境快速学习的证据；
- 理解一次性交付和产品反馈之间的关系。

### Why Anthropic

官方职位申请说明非常重视该问题。建议候选人自己完成第一稿，使用 AI 只能帮助核对结构和表达，不能生成虚假动机或经历。内容可以覆盖：

- 你理解的 Anthropic 使命与技术方法；
- 为什么“安全且有益的部署”与你的实践有关；
- 为什么是当前 FDE 职责，而不只是公司声望；
- 你希望贡献什么独特经验，以及仍想学习什么。

## 4. Coding 训练

### 重点题型

1. 分页拉取 CRM 数据，处理限流、重试和重复记录。
2. 实现带 ACL 过滤的文档搜索工具。
3. 验证模型生成 JSON，并返回可修复错误。
4. 解析 Agent Trace，找出重复调用、失败工具和缺失引用。
5. 根据用户权限过滤记录和字段。
6. 为外部 API 增加超时、指数退避和幂等键。
7. 根据工具依赖图发现循环或非法转换。
8. 编写 Eval Runner，按类别汇总成功率和失败样本。

### 限时练习标准

- 前 3–5 分钟澄清输入、权限、规模和失败语义；
- 先完成最小正确实现；
- 至少覆盖正常、空结果、非法输入、未授权和外部失败；
- 清楚区分“本题实现”和“生产加固建议”；
- 保留最后几分钟运行测试和解释取舍。

### 常见失分

- 一开始设计过度复杂框架；
- 忘记用户身份和权限；
- 只捕获异常但没有明确重试/失败策略；
- 依赖自然语言输出，没有 Schema 验证；
- 测试只覆盖 Happy Path；
- 讨论很多 AI，却没有写完基本代码。

## 5. Applied AI 作答框架

遇到“设计一个 Claude Agent”时，先按下面顺序判断：

1. **任务与失败成本**：谁做什么，错了会怎样？
2. **是否需要 Agent**：单次调用或固定 Workflow 能否完成？
3. **行动边界**：只读、草稿、审批写入还是有限自治？
4. **上下文**：什么必须在 Prompt，什么按需检索？
5. **工具**：哪些是窄接口，如何校验身份和返回错误？
6. **确定性代码**：权限、验证、重试、审计在哪里？
7. **Evals**：用哪些真实任务，检查结果还是轨迹？
8. **运营**：成本、延迟、监控、暂停和回滚。

不要把“使用 RAG、MCP、多个 Agent”当答案。每个构件都要回答为什么需要、失败模式是什么、如何验证。

## 6. System Design 六区块

### Outcome

- 用户、频率、当前基线；
- 业务指标和最低成功门槛；
- 用户为什么会采用。

### Boundary

- 数据来源、敏感等级和保留要求；
- 身份、租户、记录和字段权限；
- 明确禁止的动作和人工审批点。

### Architecture

- 模型调用、Workflow/Agent 选择；
- 检索、上下文、工具/MCP 和 Skills；
- 状态、队列、缓存、确定性服务。

### Evidence

- 20–50 个初始真实任务；
- 代码、模型和人工评分器；
- 轨迹、最终状态、对抗和安全测试。

### Operations

- 日志、Trace、告警；
- P50/P95 延迟、Token 和成本；
- 限流、降级、暂停和回滚。

### Adoption

- 影子模式、只读、草稿、审批写入；
- 培训、反馈渠道和成功负责人；
- 扩大范围的门槛与可复用模式。

## 7. Customer Discovery Case

即便正式流程没有独立 Case，这也是 FDE 的核心工作。

### 发现顺序

1. 用户和决策者是谁？
2. 当前步骤、系统和交接点是什么？
3. 哪些步骤高频、耗时、错误可观察？
4. 哪个失败不可接受？
5. 有哪些数据、权限和集成限制？
6. 什么是 4–8 周内可验证的最小 Pilot？
7. 谁批准上线，谁负责运营？

### 一个强范围示例

不要说“为全部客服构建自主 Agent”。更可交付的范围是：

> 面向一个工单类别，为内部客服生成带来源的建议回复；只读访问已授权知识库与客户记录，不直接发送或修改 CRM；用过去三个月的 40 个已解决案例评测正确性、引用、升级和延迟；达到门槛后再开放经人工确认的状态更新。

## 8. Behavioral 故事库

准备 6–8 个真实故事，每个故事能回答多个问题：

| 故事主题 | 必须包含的张力 |
| --- | --- |
| 模糊需求 | 如何找到信息并收窄，而不是等待完整规格 |
| 客户分歧 | 如何在价值、速度和风险间达成决策 |
| 生产故障 | 证据、止损、根因、修复和预防 |
| 技术取舍 | 为什么拒绝更复杂或更流行的方案 |
| 安全边界 | 如何限制能力或坚持审批，即使影响速度 |
| 失败项目 | 自己的责任、学到什么、后续行为如何改变 |
| 跨职能合作 | 如何让工程、安全、法务和业务共同推进 |
| 产品反馈 | 如何把一次客户问题变成可复用模式 |

### STAR-FDE 结构

- **Situation**：客户、流程和风险背景；
- **Task**：你的明确责任与成功指标；
- **Action**：发现、技术实现、协调和安全决策；
- **Result**：量化结果与上线/采用情况；
- **Reflection**：失败、取舍、可复用模式和下一次改进。

## 9. 四周准备计划

### 第 1 周：岗位与证据

- 阅读官方职位和候选人 AI 政策；
- 完成个人证据表；
- 写出 90 秒介绍、Why FDE 和 Why Anthropic 初稿；
- 选择 6–8 个真实故事；
- 找出一个最明显的技术或客户能力空白。

**周末产出**：证据表、故事索引、目标岗位问题清单。

### 第 2 周：生产编码与工具

- 每天完成一个 API/权限/重试/Trace/Eval 小题；
- 实现一个最小 MCP 或 Tool Server；
- 为工具写清晰 Schema、错误语义和单元测试；
- 记录一次 Agent 错用工具的原因并改进描述。

**周末产出**：可运行工具、测试和一页设计说明。

### 第 3 周：Agent、Evals 与系统设计

- 实现一个窄业务 Workflow；
- 建立 20–50 个任务的初始 Eval Suite；
- 练习三个不同领域的六区块系统设计；
- 做权限、Prompt Injection、循环和模型升级威胁分析。

**周末产出**：架构、Eval 报告、威胁模型、上线门槛。

### 第 4 周：模拟与压缩

- 进行至少两次 Coding Mock；
- 进行两次 Applied AI/System Design Mock；
- 进行一次 Customer Discovery 和一次 Behavioral Mock；
- 将每个回答压缩成 2 分钟版和 8 分钟版；
- 只修复高影响弱点，不在最后阶段无限扩充主题。

**周末产出**：最终故事库、项目演示、Recruiter 问题和复习清单。

## 10. 面试前最后核对

- 我能不用术语解释 FDE 吗？
- 我有一个真正进入生产或接近生产的 AI 故事吗？
- 我能清楚说出模型负责什么、代码负责什么吗？
- 我能为一个 Agent 写出可执行的成功标准吗？
- 我能解释 MCP 的价值，也能解释它不解决什么吗？
- 我能讲一个因证据而改变方案的故事吗？
- 我知道什么时候不应该使用 Agent 吗？
- 我能说明权限、审批、审计和回滚吗？
- 我的 Why Anthropic 是自己的真实判断吗？
- 我已经向 Recruiter 确认具体流程和 AI 使用规则了吗？

官方政策允许使用 Claude 准备面试；Take-home 和现场面试默认不能使用 AI，除非 Anthropic 明确允许。规则可能更新，面试前应重新查看 [Candidate AI Guidance](https://www.anthropic.com/candidate-ai-guidance) 并遵循 Recruiter 的具体说明。
