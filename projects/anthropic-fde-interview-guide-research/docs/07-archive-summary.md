# 07｜归档总结与后续索引

## 1. 归档结论

本项目于 2026-08-31 完成阶段性研究并归档。它已经回答：FDE 是什么、原网页提供了什么、哪些说法能够由 Anthropic 官方资料确认、企业 Agent 为什么需要确定性边界，以及如何把学习转成面试和作品证据。

当前不继续扩充岗位术语、题型猜测或第三方案例。招聘信息和产品能力具有时效性；未来使用本研究时，应重新核对 Anthropic 当前职位与官方工程资料。

## 2. 对原网页的定稿理解

研究对象是 Chill Interview 的 Anthropic FDE 面试指南。它最有价值的能力不是提供权威题库，而是把一个跨工程、AI、企业部署和客户工作的岗位拆成可学习的能力地图。

页面适合用于：

- 建立 FDE 岗位心智模型；
- 识别生产工程、Agent、企业部署、客户发现和安全评测等准备维度；
- 获取系统设计和回答组织方式；
- 发现自己的证据缺口并制定练习路线。

页面不适合用于：

- 断言 Anthropic 存在固定面试流程或固定题目；
- 把注册或付费墙后的目录当作已读取正文；
- 替代 Anthropic 当前职位、候选人政策和官方工程文档；
- 用模板包装不存在的经历。

## 3. 核心原理

FDE 的工作对象不是模型本身，而是一个能够在真实组织中被采用、被验证并安全运行的业务结果。完整闭环是：

```text
发现真实问题
→ 定义基线、风险和成功指标
→ 选择最简单可行架构
→ 接入数据与工具
→ 建立 Evals
→ 分级上线和回滚
→ 观察采用结果
→ 把重复模式沉淀为产品能力
```

企业 Agent 的基本结构是“概率推理内核 + 确定性边界”：模型负责理解、计划和综合，代码负责身份、权限、Schema、幂等、审计、错误处理和回滚。固定 Workflow 能满足需求时，不应为了展示智能而增加 Agent 自主性。

## 5. 下游落地探索

讨论从个人在军工、音视频和软件公司的经历继续展开。最重要的观察是：仿真项目经常重复实现模型制作、时间管理、指令、运动、态势显示、日志和回放。由此形成“可组合红蓝仿真工作台”探索。

这个下游项目得到的阶段性结论是：

1. 产品应定位为合成、封闭环境中的可组合仿真工作台，而不是 AFSIM 的复制品；
2. L0 交互闭环和 L1 常识合理仿真具有较高可实施性，现实验证级能力不能在 MVP 承诺；
3. 更好的方案是核心语义自研、渲染/地图/数据库等通用能力复用、专业系统后期适配；
4. 第一批价值场景应是合成红蓝原型和态势/控制软件的合成数据联调；
5. 真正的平台验收是第二个场景无需复制或修改核心内核；
6. 在没有明确试点、团队和工期时，归档比继续建设万能平台更合理。

下游项目没有运行时代码，也没有完成技术 Spike。它是产品和架构基线，不是已交付软件。详见[归档与恢复说明](../../composable-simulation-workbench/docs/07-archive-handoff.md)。

## 6. 对个人的意义

本研究把过去分散的项目经验组织成一条可以复用的能力主线：不仅能够实现系统，还能发现业务问题、控制范围、建立验证证据、处理离线和高约束环境，并判断哪些需求应进入平台、工作流、插件或一次性交付。

对于后续求职或项目说明，最有价值的不是声称“懂 FDE”，而是用真实案例证明：

- 怎样从模糊需求找到可验证的最小闭环；
- 怎样区分 Workflow、Agent 和确定性仿真；
- 怎样设计权限、失败、审计和回滚；
- 怎样把项目中的重复能力沉淀为产品候选；
- 怎样在证据不足时停止扩张并诚实归档。

## 7. 推荐阅读顺序

### 15 分钟恢复

1. 打开 [FDE Field Guide](https://yydshly.github.io/0830_codex_project/demos/anthropic-fde-interview-guide-research/)；
2. 阅读本归档总结；
3. 若关注仿真落地，再阅读[下游项目 README](../../composable-simulation-workbench/README.md)。

### 需要面试准备时

阅读岗位边界、面试能力矩阵和作品项目规格，并重新检查 Anthropic 当前职位及候选人政策。

### 需要恢复仿真产品时

先确认具体用户、首个试点场景、输入输出、目标规模、投入人员和验收指标，再按下游项目的恢复路径从 Product Charter 与 Spike A 开始。

## 8. 恢复条件

出现以下情况之一时可以恢复本研究：

- 需要针对具体地区和岗位更新 FDE 面试证据表；
- Anthropic 的职位定义、候选人政策或 Agent 工程方法出现重要变化；
- 准备真正实现企业支持 Agent 作品项目；
- 出现明确的合成仿真或态势联调试点，需要恢复下游项目；
- 需要把其他项目经验转化为 FDE 风格的业务—系统—证据案例。

恢复时不要默认沿用旧招聘事实，也不要把下游架构草案当成已经通过实测的技术结论。
