FIELD NOTE 01 / Anthropic FDE 深度研究

不是把模型卖给客户，
而是把模型变成业务结果。

Forward Deployed Engineer 进入客户真实环境，把模糊需求、Claude、企业数据、权限、安全和上线运营连接成一个可以被信任的生产系统。

先看 7 步工作闭环 直接看客服样例
  • 不是单纯 SWE
  • 不是Prompt 顾问
  • 而是端到端落地者

MENTAL MODEL

软件工程师+Applied AI Builder+企业部署者+客户发现负责人

= 安全感知的现场产品工程师

相邻角色都可能具备其中一部分能力；FDE 的稀缺性来自从问题发现一直走到生产结果。

02 / FDE 工作闭环

七步走完，Demo 才变成部署。

点选每一步，观察目标、关键问题和产出如何向下一步传递。

01

DISCOVER

先观察谁在怎样完成工作

不要从“客户想要一个 Agent”开始。找到高频步骤、事实来源、交接点和失败成本。

关键问题
谁做？多久一次？错了会怎样？
产出
工作流地图 + 当前基线

02

SCOPE

把宏大愿望压缩成窄 Pilot

选一个高频、可观察、失败可控的工作流，明确读、写、审批和禁止动作。

关键问题
最小价值单元是什么？
产出
范围 + 指标 + 风险边界

03

DESIGN

固定 Workflow 能完成，就不急着上 Agent

让复杂度服从业务价值。只有任务路径无法预先定义时，才增加自主循环或子 Agent。

关键问题
模型必须动态决策什么？
产出
架构决策记录

04

BUILD

模型负责推理，代码负责硬边界

实现工具/MCP、权限、验证、重试、幂等、审计和人工审批，而不只是 Prompt。

关键问题
哪些规则必须 100% 执行？
产出
可测试的生产组件

05

EVALUATE

检查结果、轨迹和真实最终状态

从 20–50 个真实案例开始，组合代码、模型和人工评分器，多次运行观察一致性。

关键问题
怎样证明它真的完成了任务？
产出
Eval Suite + 上线门槛

06

ROLLOUT

影子 → 只读 → 草稿 → 审批写入

逐级开放能力，观察采用、成本和事故信号；每一级都有暂停和回滚条件。

关键问题
何时扩大，何时退回？
产出
上线与运营计划

07

CODIFY

把一次项目变成产品能力

识别可复用的连接器、Skill、Eval、权限策略和平台缺口，反馈给产品与工程。

关键问题
下一位客户能少做什么？
产出
复用资产 + 产品反馈

03 / 企业 Agent 原理

Claude 是推理内核，
不是整个生产系统。

点击架构层，理解模型、上下文、工具和确定性边界各自负责什么。

LAYER 01

技术选择从业务结果倒推

如果没有用户、基线、失败成本和成功指标，就无法判断是否需要 Agent，也无法设计评测。

先问谁要完成什么任务？错误会造成什么？

LAYER 02

必须 100% 执行的规则交给代码

身份、ACL、字段白名单、重试、幂等和审批不应只写在 Prompt 中；模型不能成为权限系统。

原则概率推理内核 + 确定性安全边界

LAYER 03

先 Workflow，必要时才 Agent

固定路径提供可预测性；开放任务才让 Claude 根据环境反馈动态决定步骤。Agent 用成本和风险换灵活性。

选择简单调用 → Workflow → Agent → 子 Agent

LAYER 04

MCP 负责连接，上下文工程负责选择

MCP 让 AI 接入外部系统，但不自动解决权限和质量。上下文要少而相关，工具要职责清晰且返回 Token 高效。

提醒连接更多数据 ≠ 获得更好答案

LAYER 05

不能只检查模型最后说了什么

同时检查完整轨迹、工具调用和外部系统最终状态，并用多次 Trial 衡量非确定性系统的一致性。

证据Task + Trial + Grader + Trace + Outcome
01

最小复杂度

只有 Evals 证明价值时才增加 Agent 层级。

02

最小上下文

按需加载高信号信息，避免上下文污染。

03

最小权限

读取、草稿、写入和外发必须分级授权。

04 / 端到端样例

同一个“客服 Agent”，
Demo 和 FDE 方案差在哪里？

用“账户访问问题”样例，把抽象原理放回真实工作流。

INCOMING TICKET / #AC-1048

“我换了手机后无法登录。请帮我恢复账户，我很着急。”
企业客户含身份风险需要查 CRM 与政策
01整段 Prompt塞入工单和大量文档
→
02Claude 回答看起来合理
→
03直接发送无权限与审批

为什么危险

  • 无法证明引用来自有效政策
  • 可能泄漏其他客户信息
  • 模型声称完成，不代表 CRM 真的改变
  • 没有可重复的 Eval 与回滚门槛
01身份与范围租户 + ACL
→
02窄工具检索CRM + 有效政策
→
03结构化草稿回复 + 引用 + 风险
→
04规则校验Schema + 引用 ID
→
05人工审批高风险升级

TOOL RESULT

仅返回当前租户 3 个必要字段服务端执行 ACL

MODEL OUTPUT

草稿 + 2 个来源 + SECURITY_REVIEW严格 JSON Schema

EVAL OUTCOME

检查是否正确升级，而非是否“说得像”多次 Trial + 最终状态
!

样例结论：FDE 的价值不在“回答更华丽”，而在权限、证据、动作边界和上线方法都可解释、可测试、可回滚。

FAILURE CLINIC

看到失败，先判断它属于哪一层

把所有问题都归因于 Prompt，会错过更常见的系统与采用问题。

症状幻觉、遗漏、循环、工具选错
先查Trace、上下文、工具描述、任务分解
证据失败集 + 多次 Trial + 轨迹评分
症状串租户、重复写入、旧政策、动作未生效
先查身份、ACL、版本、幂等、真实 Outcome
证据集成测试 + 审计日志 + 回滚演练
症状用户不用、修改过多、节省时间不明显
先查工作流摩擦、问题选择、信任与培训
证据采用率 + 修改量 + 周期与定性访谈

05 / 使用场景与扩展方向

不是所有工作都需要 Agent，
但所有落地都需要边界。

先看任务是否开放、结果是否可验证、动作是否可逆，再决定自治程度和扩展路线。

AGENT FIT CHECK

先判断任务形状，再选择技术形状

这不是分数测验。前 3 项判断是否需要动态决策，后 3 项判断能否安全试点。

选择符合当前任务的条件
尚未判断先勾选任务的真实条件

不要从“我想做 Agent”开始；从任务是否开放、可验证和可控开始。

HIGH-CONSTRAINT BUSINESS LAB

在高约束行业里，
先选业务结果，
再选智能形态。

军工不是一个单一“AI 场景”。作战辅助、训练推演、防护验证、物理仿真、多模态处理和装备保障追求不同结果；模型、Agent 和仿真引擎只能从结果反推。

GLOSSARY

12 个术语，够你恢复整套心智模型

输入中文或英文，例如 “权限”“MCP”“评测”。

01

Workflow

模型和工具沿预先定义的代码路径执行；适合步骤明确、要求稳定的任务。

02

Agent

模型根据环境反馈动态决定下一步和工具；用成本与风险换灵活性。

03

MCP

连接 AI 应用与外部数据、工具和工作流的开放标准；它不是权限系统。

04

Tool

确定性系统与非确定性 Agent 的契约；职责、输入、错误和权限必须清晰。

05

Context Engineering

选择模型当前最需要的指令、工具、数据、历史和状态，而不是塞入全部信息。

06

Agent Skill

可复用的领域指令、流程知识、参考材料和代码，描述某类任务应怎样完成。

07

Subagent

为专业子任务隔离上下文和工具；只有并行或专业化收益大于通信成本时才使用。

08

Eval

给系统任务并用评分逻辑判断成功；它把模糊的“效果好”变成可回归的证据。

09

Trace

一次运行的完整过程，包括模型输出、工具调用、中间结果和错误恢复。

10

Outcome

任务结束后外部环境的真实状态；Agent 说“完成”不等于 Outcome 成功。

11

Human-in-the-loop

人在高风险判断或动作前确认，不是简单地在流程末尾看一眼。

12

Least Privilege

只提供完成当前任务所需的最小数据和动作能力，并在工具端再次强制执行。

没有匹配术语。尝试“工具”“Agent”“评测”或“权限”。
