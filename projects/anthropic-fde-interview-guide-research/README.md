## 结论先行

FDE 不是“更会写 Prompt 的软件工程师”，而是能在客户真实系统里完成以下闭环的人：

```text
发现业务问题 → 界定风险与成功指标 → 选择最简单可行架构
→ 接入数据与工具 → 建立评测 → 小范围上线 → 监控与回滚
→ 扩大采用 → 把重复模式反馈给产品团队
```

Chill Interview 页面最有价值的地方，是把这个混合岗位拆成一张准备地图：生产工程、Agent 系统、企业部署、客户发现、安全可靠性和跨职能沟通。它适合作为学习大纲和练习题来源，不适合作为“真实面试题库”或固定面试流程的证据。

## 研究问题

- FDE 的岗位本质是什么，为什么模型公司需要这种角色？
- 页面实际提供了什么能力，它的内容组织原理是什么？
- 页面中哪些内容可由 Anthropic 官方资料确认，哪些只是第三方推测？
- FDE 需要掌握的 Agent 技术和企业交付方法如何组成完整系统？
- 如何把阅读结果转化为面试准备与可验证作品，而不是停留在术语记忆？

## 背景与假设

- **已知背景**：Anthropic 当前公开招聘 Forward Deployed Engineer。官方职责包括进入战略客户环境、用 Claude 构建生产应用、交付 MCP Server、子 Agent 和 Agent Skills，并总结可复用的部署模式。
- **核心假设**：页面最可靠的部分不是面试轮次预测，而是从公开岗位信号中归纳出的能力结构。
- **成功标准**：读者无需回看聊天记录，即可解释 FDE、评估页面可信度、设计一个企业 Agent，并制定面试和作品计划。
- **不在范围内**：绕过付费墙、宣称掌握 Anthropic 内部题库、代替候选人虚构经历、保证面试结果。

## 方法

研究采用四步法：

1. 记录页面在 2026-08-30 无登录状态下可访问的内容与目录。
2. 以 Anthropic 当前 FDE 职位页为岗位事实基线。
3. 用 Anthropic 官方工程文章核验 Workflow/Agent、上下文、工具和 Evals 的技术主张。
4. 把“页面原文事实”“官方确认事实”“研究推断”和“准备建议”分开书写。

## 关键发现

### 1. FDE 的交付对象不是模型，而是业务结果

FDE 要对“系统是否进入生产、是否可靠、是否被使用”负责。模型调用只是中间组件。优秀候选人会从用户、流程、数据、权限、失败成本和成功指标开始，而不是从“我要做一个 Agent”开始。

### 2. 岗位的稀缺性来自跨域闭环

单独掌握编码、Prompt、架构或客户沟通都不够。FDE 的门槛是能把这些能力串起来，并在模糊、高风险、跨组织的环境中持续推进。

### 3. 企业 Agent 的基本结构是“概率推理内核 + 确定性边界”

Claude 负责理解、计划、选择工具和综合；确定性代码负责身份、权限、过滤、验证、重试、幂等、审计和回滚。越高风险的写操作，越需要更窄的工具接口和更强的人工审批。

### 4. Evals 是需求、工程与运营的共同语言

Evals 不只是上线前测试。它把“什么叫成功”转为任务、试验、评分器、轨迹和最终状态检查，也让模型升级、Prompt 改动和工具变更具备可比较的回归基线。

### 5. 页面有明确的信息边界

页面公开正文到“Enterprise AI System Design”中的十步设计框架为止；后续客户发现、价值观、行为面试、职级、准备计划、薪酬、要求和 FAQ 只在目录中出现，正文要求注册或付费。因此，本项目不声称已读取这些付费内容。

## 局限与风险

- Anthropic 未公布统一 FDE 面试循环；团队、地区、客户行业和职级都可能改变轮次。
- 第三方指南可能混合历史职位、相邻岗位和作者推断。
- 招聘信息具有时效性；本项目的事实截止日期为 2026-08-30。
- 本项目没有候选人的简历和目标地区，个人差距判断只能给出通用框架。
- “强回答”模板不能替代真实经历。把模板套在虚构经历上会降低可信度，也违反招聘诚信。
