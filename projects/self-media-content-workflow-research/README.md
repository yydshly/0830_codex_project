## 结论先行

[`yanhua1010/self-media-content-workflow`](https://github.com/yanhua1010/self-media-content-workflow) 是一套面向 AI Agent 的内容生产与经营工作流，不是一个自带模型、热点数据库和全平台发布账号的独立应用。

它已经覆盖“想法 → 简报 → 研究 → 多平台创作 → 视觉/视频方案 → 质检 → 草稿或发布包 → 数据复盘”的完整业务架构。真正执行搜索、图片生成、视频合成、平台写入和数据读取时，它会调用当前 Agent 环境已有的工具；工具不可用时则交付可手动完成的降级产物。

对我们最重要的价值，是把现有研究项目和真实工作过程持续转化为内容资产，并为 Agent 工作流提供一套可借鉴的模块化、状态化和人工审批架构。

网页图解见 [`web/index.html`](web/index.html)，从想法到待发布包的完整案例见 [`web/demo.html`](web/demo.html) 和 [`demo-case/`](demo-case/README.md)，第一阶段完整拆解见 [《能力、原理、场景与意义》](docs/第一阶段研究报告.md)。上游源码固定在提交 [`c460299`](UPSTREAM.md)。

## 研究问题

1. 这个库实际具备哪些能力，哪些只是依赖外部工具的条件能力？
2. 它怎样把多个 Skill、任务状态、确认点和工具适配连接成端到端流程？
3. 哪些内容团队和创作任务适合使用，哪些目标不适合？
4. 它对我们的研究内容生产、项目传播和 Agent 架构建设有什么意义？

## 第一阶段结论

### 它已经提供的

- 9 个可独立安装的 Skill：1 个总控和 8 个单一职责模块。
- 创作简报、账号策略、选题池、内容日历和多平台内容编排。
- X、小红书、公众号、视频号和抖音的表达规范与交付字段。
- 短视频钩子、口播、分镜、字幕、录屏和数字人制片流程。
- 任务卡、内容注册表、版本、质量门和发布审批状态。
- 单篇、周度和月度数据复盘框架，以及单变量实验规则。
- 通过外部 `wenyan CLI` 写入微信公众号草稿箱的适配流程。
- 17 份参考规范、12 个输出模板和 9 份 OpenAI Agent 元数据。

### 它没有直接提供的

- 自有大模型、图片模型、视频模型或数字人生成服务。
- 内置热点数据库、平台数据仓库或通用竞品爬虫。
- 小红书、抖音、视频号和 X 的完整发布客户端。
- 无人值守的群发、点赞、关注、评论或私信自动化。
- 训练式风格学习、自动因果归因或完整 BI 系统。

因此，它的核心资产是“Agent 应该如何完成内容工作”的可执行规范，而不是替代所有外部工具的应用程序。

## 研究方法

1. 固定上游 `main` 的完整提交和版本，保留 MIT 许可证。
2. 阅读 9 个 `SKILL.md`、17 份参考资料、12 个模板、Agent 元数据和 CI。
3. 区分仓库自身能力、Agent 推理能力、运行时工具能力和人工操作。
4. 使用上游校验脚本验证 Skill 结构、相对链接、元数据和未处理 TODO。
5. 将观察事实、架构推断、适用场景和对我们的建议分别记录。

## 运行与复现

本阶段没有安装公众号凭据或执行任何平台写操作。结构验证使用上游自带、无第三方依赖的脚本：

```powershell
cd projects/self-media-content-workflow-research/upstream
python scripts/validate.py
```

本地查看网页：

```powershell
cd projects/self-media-content-workflow-research/web
python -m http.server 4177 --bind 127.0.0.1
```

浏览器打开 <http://127.0.0.1:4177/>；完整案例位于 <http://127.0.0.1:4177/demo.html>。网页静态检查：

```powershell
python projects/self-media-content-workflow-research/verify_web.py
```

研究仓库级检查：

```powershell
python scripts/research_hub.py check
python scripts/research_hub.py build --output .tmp/research-site
```

## 当前局限

- 本阶段是源码和流程审计，尚未用真实账号完成一次端到端发布。
- 尚未安装 9 个 Skill 到独立测试 Agent，对跨 Agent 的触发和续跑一致性仍需实验。
- 没有使用真实后台数据验证分析模块的归因质量。
- 平台规则会变化，仓库中的经验规则不能替代发布时的官方核验。
