# 总案例报告：从真实研究到三平台待发布包

## 1. 案例结论

`self-media-content-workflow` 能把一个已有事实基础的内容想法组织为可追溯、可审核、可返工的多平台内容包。它提供的是 Agent 工作方法、文件协议、状态机与人工确认点，不是自带账号、生成模型或无人值守发布能力的内容 SaaS。

本案例使用 Research Lab 已完成的 `genart-skill` 研究作为唯一母题，完成小红书、公众号和 60 秒短视频三套平台原生稿。全过程没有登录账号、创建草稿或真实发布，外部写入始终为 `0`。

## 2. 场景与触发

- 场景编号：`SCENE-RL-001`。
- 组织：Research Lab。
- 触发消息：“请用 self-media-content-workflow 演示从想法到可发布内容包的完整路径。本次选择已完成实测的 genart-skill 研究作为内容原料；必须使用真实实验，不要登录账号，也不要假设已经发布。”
- 角色关系：`self-media-content-workflow` 是被演示的工作流；`genart-skill` 是可替换的内容原料，不是运行依赖。
- 目标受众：AI 工具研究者、创意编码者、评估 Agent Skill 的团队。
- 演示计划：90 分钟计划预算，不是实测效率或生产 SLA。
- 默认终点：`AWAITING_USER`。

## 3. 真实输入

| 输入 | 在案例中的用途 | 去向 |
| --- | --- | --- |
| 固定源码与上游提交 | 固定版本和可引用边界 | 证据包、公众号方法部分 |
| 正常 fixture 与故障对照 | 证明 A-B-A 检查和 4 项 FAIL | 证据图、小红书过程页、视频钩子 |
| 9-seed 网格图 | 提供真实而非虚构的视觉证据 | 小红书封面、公众号头图、视频 04–10 秒 |
| 500-seed census | 区分目标权重与实测分布 | 数据图解、标题与质量门披露 |

## 4. 九阶段执行结果

| 阶段 | 关键决定 | 保存产物 |
| --- | --- | --- |
| 01 想法 | 任务是“研究转内容”，不是直接写正文 | 内容任务卡 v0 |
| 02 简报 | 核心判断是“增加专业流程，不是增加绘画模型” | 受众、目标、禁区、默认值 |
| 03 证据 | 共享事实，不共享各平台正文 | 可引用事实、来源、不可说边界 |
| 04 平台 | 三个平台分别承担发现、解释和快速认知 | 平台路由与能力预检 |
| 05 创作 | 不使用一稿三剪 | 三套平台原生稿 |
| 06 素材 | 复用研究生成的真实网格图 | 视觉任务、分镜与来源说明 |
| 07 质检 | 记录修改，而不是只写“已检查” | 六道质量门与复检结论 |
| 08 发布 | 写完不等于允许发布 | 手动发布包与 `AWAITING_USER` |
| 09 复盘 | 只演示分析结构 | 明确标注的合成数据与单变量实验 |

## 5. 三平台产物

| 平台 | 核心任务 | 完整产物 |
| --- | --- | --- |
| 小红书 | 搜索发现与收藏 | 3 个标题、8 页组图、正文、话题、首评 |
| 公众号 | 建立深度理解与信任 | 3 个标题、摘要、完整长文、配图需求 |
| 短视频 | 用冲突形成快速认知 | 3 个钩子、60 秒口播、9 镜分镜、字幕要点 |

三套内容共享同一证据包，但目标、结构、最强证据和唯一行动不同，因此不能把同一正文简单裁切三次。

## 6. 人工审核与状态机

批准进入本地草稿准备必须同时满足：

1. 九个阶段全部检查，计数为 `9 / 9`。
2. 只选择一个主平台。
3. 事实可回溯、素材与版权、平台结构、零外部写入四项确认全部完成。

满足后生成 `READY_FOR_DRAFT_HANDOFF` 本地演示回执。它不是终稿确认、账号授权或真实发布授权。

### 返工分支

| 退回原因 | 返回阶段 | 重新失效的范围 |
| --- | --- | --- |
| `FACT` 事实或引用需要复核 | 03 证据 | 证据及其全部下游阶段 |
| `ASSET` 素材或版权需要完稿 | 06 素材 | 素材、质检、发布、复盘 |
| `PLATFORM` 平台结构需要调整 | 04 平台 | 平台及其全部下游阶段，同时清空主平台选择 |
| `COMPLIANCE` 合规披露需要确认 | 07 质检 | 质检、发布、复盘 |

进入返工后状态为 `REVISION_IN_PROGRESS`。目标阶段及下游从已检查集合移除，四项人工确认清空；重新走到 `9 / 9` 后回到 `AWAITING_USER`，必须再次完成四项确认才能批准。

## 7. 质量与真实性

### 已证明

- 真实研究输入可以形成三种平台原生结构。
- 内容事实可以回到固定源码、实验输出和证据文件。
- Agent、运行时工具和人类负责人的职责能够落到状态和交付物。
- 批准、退回、定向返工、重新提交和重启能够在零外部写入下完整演练。

### 没有证明

- 90 分钟是实际生产效率或服务承诺。
- 内容已经在真实账号发布或获得真实运营数据。
- 安装仓库即可获得账号、图片模型、视频模型或无人值守群发能力。
- 合成复盘数据可以替代真实运营归因。

## 8. 交付文件

1. `scenario.md`：业务现场、角色、输入、计划和完成定义。
2. `content-task.md`：任务状态与创作简报。
3. `evidence-pack.md`：事实、来源和可说 / 不可说边界。
4. `platforms/xiaohongshu.md`：小红书完整成稿。
5. `platforms/wechat.md`：公众号完整成稿。
6. `platforms/short-video.md`：短视频完整方案。
7. `quality-gate.md`：六道质量门。
8. `publishing-package.md`：三平台发布清单和授权缺口。
9. `analytics-demo.md`：合成复盘数据与唯一实验。
10. `approval-record.md`：审核门槛、批准、退回和重启规则。
11. `case-report.md`：本总案例报告。

## 9. 对 Research Lab 的意义

这套案例证明，我们可以把已经完成的研究工作继续转化为内容资产，同时保留原研究的证据、失败记录和真实性边界。更重要的是，它给后续 Agent 系统提供了一套可借鉴的结构：任务文件负责续跑，阶段状态负责控制，工具能力负责执行，人工确认负责方向与权限。

下一阶段若进入真实运营，应先选择一个主平台，只授权“最终预览或创建草稿”，验证账号工具和排版结果后，再单独决定是否发布。
