# 完整演示案例：一个生成艺术 Skill，真正增加了什么？

这是 `self-media-content-workflow` 的端到端演示包。母题和证据来自 Research Lab 已完成的 `genart-skill-research`，平台稿件则是为本演示独立创作、尚未实际发布的内容。

## 演示目标

把一句想法推进为一组可人工发布的内容资产，并保留每个阶段的输入、决策、证据、质量状态和下一步动作。

```text
想法 → 创作简报 → 证据包 → 平台预检 → 三平台创作
     → 视觉与分镜 → 质量门 → 手动发布包 → 数据复盘
```

## 文件清单

| 阶段 | 产物 | 文件 |
| --- | --- | --- |
| 场景 | 角色、输入、限制、时间线与完成定义 | `scenario.md` |
| 想法 / 状态 | 内容任务卡 | `content-task.md` |
| 证据 | 可引用事实、边界与来源 | `evidence-pack.md` |
| 小红书 | 3 个标题、8 页组图脚本、正文、话题、首评 | `platforms/xiaohongshu.md` |
| 公众号 | 3 个标题、摘要、完整正文、配图需求 | `platforms/wechat.md` |
| 短视频 | 3 个钩子、60 秒口播、9 镜分镜、发布字段 | `platforms/short-video.md` |
| 质量 | 六道质量门及复检结论 | `quality-gate.md` |
| 发布 | 三平台手动发布清单和阻塞状态 | `publishing-package.md` |
| 复盘 | 合成演示数据、归因限制和下一次实验 | `analytics-demo.md` |
| 审核 | 主平台选择、人工确认、批准 / 退回与真实性边界 | `approval-record.md` |
| 总结 | 输入、九阶段、三平台、返工分支、结论与意义 | `case-report.md` |

## 当前状态

- 内容与素材：单一场景、演示稿和交付文件已完成。
- 事实核验：通过，关键数字均可回到研究项目。
- 终稿确认：本案例只模拟内部成稿，不代表用户对真实账号终稿的确认。
- 发布授权：**否**。
- 工作流状态：`AWAITING_USER`。
- 审核演练：网页只有在 9 / 9 阶段已检查、选择主平台并完成 4 / 4 人工确认后，才允许生成批准回执；退回时会按原因返回证据、素材、平台或质检阶段，使目标及下游检查失效，重新到 9 / 9 并再次人工确认后才能批准。
- 下一步唯一动作：如果要进入真实运营，由账号负责人选择一个主平台并明确授权创建草稿或手动发布。
