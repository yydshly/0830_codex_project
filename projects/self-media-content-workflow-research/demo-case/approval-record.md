# 人工审核回执：SCENE-RL-001

> 这是生产前演练使用的本地决策记录。默认状态为 `AWAITING_USER`；任何演示决定都不会登录账号、创建草稿或发布内容。

## 审核对象

- 场景：Research Lab 将已完成的 `genart-skill` 研究转为三平台待发布包。
- 候选主平台：小红书、公众号、短视频。
- 审核人：内容负责人。
- 外部写入：`0`。

## 批准门槛

只有同时满足以下条件，才能在演示页面生成“批准进入本地草稿准备”的回执：

1. 9 个工作阶段已经全部检查，页面显示 `9 / 9`。
2. 已选择且只选择一个主平台。
3. 关键事实和数字可以回到 `evidence-pack.md`。
4. 素材来源与版权已经人工核对。
5. 平台结构已经人工复核，不是一稿三发。
6. 审核人理解本次操作不会创建草稿或真实发布。

批准后的演示状态为 `READY_FOR_DRAFT_HANDOFF`。它只表示内容包可以继续进行最终素材和平台预览核验，不等于真实账号授权。

## 退回路径

审核人可以不完成批准门槛，直接选择一个主要原因并生成 `CHANGES_REQUESTED` 回执。页面会把原因映射到准确的返工阶段：

| 原因码 | 返回阶段 | 失效范围 |
| --- | --- | --- |
| `FACT` | 证据 | 证据及其全部下游阶段 |
| `ASSET` | 素材 | 素材及其全部下游阶段 |
| `PLATFORM` | 平台 | 平台及其全部下游阶段；同时重新选择主平台 |
| `COMPLIANCE` | 质检 | 质检及其全部下游阶段 |

开始返工后，状态变为 `REVISION_IN_PROGRESS`，目标阶段及其下游会从“已检查”集合移除，四项人工确认和退回原因被清空。重新检查到 `9 / 9` 后，页面记录 `REVISION_READY_FOR_REVIEW` 并回到 `AWAITING_USER`；审核人必须重新完成主平台和 `4 / 4` 人工确认，才能再次批准。

退回后的唯一下一步，是按上述映射修订并重新运行受影响链路，而不是绕过审核继续发布。

## 会话日志与重启

- 当前浏览器会记录演示就绪、阶段首次检查、批准、退回和审核重置事件；每一项都明确外部写入为 `0`。
- “重置本次审核”只清空表单和回执，保留已经检查的阶段。
- “重新开始完整演示”会清空阶段、表单、回执与旧日志，回到想法阶段和 `1 / 9`。
- 日志和决定都不持久化；刷新页面后从默认演示状态重新开始。

```yaml
receipt_id: DEMO-RL-001-APPROVED-WECHAT

primary_platform: 公众号
human_checks: 4/4
external_writes: 0
next_action: 完成公众号最终封面和编辑器预览核验，再单独申请账号授权
truth_boundary: 本地演示决定，不是终稿确认或真实发布授权
```

## 真实性边界

- 页面中的批准或退回仅保存在当前浏览器状态，刷新后回到 `AWAITING_USER`。
- 回执样例不是实际签署记录，也没有写入真实内容台账。
- 真实创建草稿、排版预览或发布仍需要账号负责人另行授权并提供对应工具能力。
