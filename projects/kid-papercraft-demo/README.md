# Kid Papercraft 情绪价值内容方法研究

在线研究页：<https://yydshly.github.io/0830_codex_project/demos/kid-papercraft-demo/>

上游仓库：<https://github.com/kaomei/kid-papercraft>

## 一句话结论

`kid-papercraft` 本身是一个面向“儿童纸艺生日短片”的领域 Prompt Skill：它采集生日信息、选择固定角色模板，并输出三幕英文视频 Prompt 与中文配音建议，不直接生成图片、视频或音频。

本轮研究真正沉淀出的可扩展能力，是一套更上位的**个性化情绪价值内容方法**：

> 把用户难以直接表达的情感，转译成可观看、可保存、可赠送的个性化内容。

统一创作公式：

```text
人物 / 对象 + 关系 / 愿望 + 目标情绪 + 象征性陪伴者 + 场景 + 媒介
```

纸艺、动画和短视频只是表达媒介。核心竞争力不是风格数量，而是能否理解“谁想让谁感到什么”，并把这种主观意愿变成具体的关系动作、个人证据和可留下的产品结果。

## 价值目标

| 价值层 | 希望产生什么 | 设计时要回答的问题 | 可观察结果 |
| --- | --- | --- | --- |
| 情绪价值 | 被陪伴、被鼓励、被理解、被认可 | 此刻希望对方感受到什么？ | 作品是否出现倾听、牵手、回应、共同完成等具体动作 |
| 关系价值 | 亲子、伴侣、朋友、宠物、代际关系被看见 | 我们之间什么值得被保存？ | 是否使用真实的共同路线、物件、声音、习惯或事件作为证据 |
| 仪式价值 | 生日、纪念、毕业、成长、重逢、告别拥有节点 | 这个时刻最终留下什么？ | 是否形成可再次观看、补充、赠送或共同参与的内容载体 |

这里的“情绪价值”不是泛化煽情，也不是保证接收者一定产生某种心理变化。更准确的链路是：

```text
情绪状态 → 情绪需求 → 关系价值 → 转化结果
```

产品评估应看可观察信号，例如当事人是否愿意补充材料、是否认出共同经历、是否形成可重访的档案，而不是承诺“看完一定被治愈”。

## 典型示例与特点

| 对象与方向 | 表达者的主观意愿 | 产品目标 / 效果 | 示例特点与推荐媒介 |
| --- | --- | --- | --- |
| 孩子 × 喜欢的奥特曼 | “希望你在害怕时，也记得有人愿意牵着你往前跑。” | 把角色喜爱转成勇气和安全感 | 英雄应牵手、回望、并肩行动，而不是在旁边合影；推荐动作短片、英雄来信、成长任务卡 |
| 长辈 × 远方家人 | “希望你知道，我们仍在认真听你讲那些旧故事。” | 创造团聚感并保存家庭记忆 | 以声音、旧物和可回信机制替代抽象煽情；推荐声音邮局、家族声音档案 |
| 伴侣 × 共同生活证据 | “希望你知道，那些普通日子我一直记得。” | 确认持续关注与共同承诺 | 用路线、物件、习惯和两人补充的细节建立证据；推荐纪念日档案、互动相册 |
| 宠物 × 主人 | “希望这段无条件的陪伴，有一处可以被好好保存。” | 表达治愈、珍惜或温柔告别 | 保留真实日常动作，避免空洞人格化；推荐陪伴纪念册、年度仪式盒 |
| 现在的自己 × 未来的自己 | “希望你先被此刻的自己接住，再重新出发。” | 提供自我确认与阶段性鼓励 | 让两个时间版本发生具体对话；推荐未来回信、阶段路线册 |
| 毕业生 × 老师与同伴 | “希望你看见，成长从来不是一个人完成的。” | 同时承载感谢、告别和下一程期待 | 用共同任务、教室和校园路线串联关系；推荐毕业影像册、共同地图 |
| 普通人 × 童年偶像 | “希望小时候的愿望，在今天被认真回应一次。” | 提供梦想被看见的确认感 | 偶像不是背景装饰，而应与人物完成一个共同动作；推荐电影感合成短片、纪念海报 |

可扩展媒介包括电影感实拍、绘本、漫画、复古家庭录像、梦境短片、音乐影像、会说话的照片、未来来信、相册、海报、互动故事和数字纪念品。媒介应服务关系目标，而不是反过来决定内容。

## 真实奥特曼测试：最重要的结论

用户希望使用真实孩子照片，生成多个具名奥特曼像家庭一样与孩子互动，并强调主动陪伴和动作感。测试暴露了三个不同问题：

1. **关系氛围成立，不等于人物身份成立。** 罗索、布鲁和格丽乔围绕孩子的站位、照顾动作能形成家庭感，但单张斜侧照片不足以提供正脸、体型和全身几何，生成结果变成了另一个孩子。
2. **动态构图成立，不等于视频可交付。** 牵手跑步、回望和跟拍改善了坐姿合影的僵硬感，却要求模型补画更多脸部和身体信息，反而放大身份偏差。
3. **写“保持一致”不是身份锁。** Prompt 只能表达约束，不能替代多视角证据、参考控制、关键帧审批、逐镜头复核和后期合成。

本轮检查的用户测试片约为 `10.0s / 1280×720 / 24fps`。镜头跟随和奔跑动作成立，但画幅变为横屏，首帧约束和经典战衣细节漂移，第三位英雄后段才出现，并带有水印。它证明静态图只是生产过程中的审批层，不等于最终效果。

### 推荐生产路径

真实人物项目优先选择：

```text
实拍 5–10 秒动作视频
→ 保留真实脸、体型和自然动作
→ 合成或受控生成陪伴角色与场景
→ 分镜复核
→ 声音、字幕、节奏与导出
```

只有照片时选择：

```text
正面 + 45° + 侧面 + 全身 + 目标服装
→ 建立身份参考包
→ 生成并人工审批动作关键帧
→ 短镜头图生视频
→ 逐镜头检查身份、角色数量、动作和经典造型
→ 剪辑交付
```

因此，“合理、清晰的入口人物照片”是必要条件，但不是充分保证。真实人物短视频通常比一张照片更适合作为动作内容的身份入口。

> `web/assets/real-tests/identity-reference-input-board-sample-v1.png` 和 `multi-view-identity-to-ultraman-action-sample-v1.png` 使用的是虚构儿童，只用于说明多视角方法，绝不代表用户家的孩子。

## 上游库的真实能力

上游固定提交：`3ff307c51377b2ce8378106ac95782215130f3e0`（`main`，获取于 2026-08-30）。

工作原理：

```text
收集画幅、角色、姓名、年龄、外貌
→ 在 5 个动画主题模板中路由
→ 替换模板变量
→ 追加纸张材质、柔光、轻缓运镜等固定风格锚点
→ 输出 3 × 10 秒英文 Prompt、中文配音与剪辑建议
```

仓库直接提供：

- 引导式信息收集；
- 汪汪队、小猪佩奇、奥特曼、海绵宝宝、哆啦A梦五套模板；
- 三幕故事结构和统一纸艺视觉后缀；
- 英文视频 Prompt、中文配音和制作说明。

仓库不直接提供：

- 图片或视频生成 API；
- MP4、配音、字幕或剪辑文件；
- 人脸身份锁与跨镜头角色一致性；
- 自动重试、质量评估、成本和隐私治理；
- 第三方动画角色的商业授权。

因此，上游更准确的定位是**领域提示词编排器 / Prompt Skill**，不是“直接文生视频”产品。

## 沟通与研究演进

| 阶段 | 关键问题 | 形成的沉淀 |
| --- | --- | --- |
| 1. 能力辨析 | 这个库能否直接生成视频？ | 确认其输出是 Prompt 包，而非媒体文件 |
| 2. 展示能力 | 如何让人看懂原理、样例和效果？ | 建立能力页、三幕样例、上游样片和边界说明 |
| 3. 场景与风格 | 除纸艺和儿童生日还能做什么？ | 形成四类场景、十二种风格和风格选型路线 |
| 4. 创意方法 | 不继续堆模板，如何持续产生方向？ | 形成七维创意语法、五步方法和四问筛选 |
| 5. 对象与情绪 | 能否服务成人、宠物、团队、地方文化？ | 形成八类对象、四层价值、八种产品和二十个种子 |
| 6. 产品化表达 | 如何说明产品目标、效果和主观意愿？ | 建立概念图、图片 Prompt、效果预演和输入/参与/留下链路 |
| 7. 真实人物测试 | 为什么生成的孩子不是照片中的孩子？ | 识别单图信息不足、全图重绘和动作放大误差问题 |
| 8. 动态测试 | 图怎样到最终视频？ | 明确真实视频优先、多视角照片备选、审批关键帧和逐镜头复核 |
| 9. 最终抽象 | 这项能力的本质价值是什么？ | 收束为个性化情绪价值 / 关系表达内容方法 |

完整判断、证据和边界见 [沟通与研究结论汇总](docs/research-synthesis.md)。

## 本地运行与验证

要求 Python 3.9+，网页无需安装前端依赖。

```powershell
cd projects/kid-papercraft-demo
python demo/verify_demo.py
python -m http.server 4173 --bind 127.0.0.1
```

打开 <http://127.0.0.1:4173/web/>。

从仓库根目录构建 GitHub Pages 产物：

```powershell
python scripts/research_hub.py check
python scripts/research_hub.py build --output .tmp/research-site
```

推送 `main` 后，`.github/workflows/pages.yml` 会构建研究门户并部署该页面到 `/demos/kid-papercraft-demo/`。

## 局限、隐私与版权

- 真实儿童素材需获得监护人同意，采用最小化收集、限制访问、明确保存期限和删除策略。
- 单张照片、多角度照片乃至参考视频都不能单独保证生成模型做到身份完全一致；必须保留人工审批与回退路线。
- 多个独立视频镜头可能发生人物、服装、光线、角色数量、战衣细节和动作连续性漂移。
- 上游 MIT 许可证不等于获得奥特曼、哆啦A梦等第三方 IP 的商业使用权。公开或商业产品应使用原创角色或单独取得授权。
- 页面中的概念图和虚构身份样例用于创意与方法研究，不是产品截图，不证明情绪效果，也不代表真实人物。

## 下一步建议

- 将价值方法沉淀为结构化 Brief：对象、关系、愿望、证据、目标情绪、媒介、禁区。
- 为真实人物建立授权、素材质量检查、身份包、关键帧审批和删除流程。
- 将长视频拆为 3–5 秒短镜头，逐段评价身份、角色数量、经典造型、动作和画幅。
- 优先发展原创陪伴角色，降低第三方 IP 商业授权风险。
- 用真实用户访谈和留存行为验证价值，而不是以“风格好看”代替产品验证。
