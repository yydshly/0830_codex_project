# Kid Papercraft 沟通与研究结论汇总

## 1. 研究结论

### 上游库是什么

`kaomei/kid-papercraft` 是一个领域 Prompt Skill。它把儿童生日信息填入五套动画角色模板，编排为三幕纸艺定格视频 Prompt、中文配音建议和剪辑说明。

它不包含图片/视频模型调用、身份控制、音频合成、字幕、剪辑导出或质量评估，因此不能被描述为“直接文生视频工具”。

### 本轮研究沉淀是什么

从上游的窄场景继续抽象后，可复用的方法是：

> 先理解表达者希望一个对象感到什么，再把这种意愿变成具体关系动作、个人证据、场景、媒介和可留下的结果。

名称可以概括为：

- 个性化情绪价值内容方法；
- 关系型情绪内容生成方法；
- 主观意愿到内容产品的转译方法。

统一公式：

```text
人物 / 对象 + 关系 / 愿望 + 目标情绪 + 象征性陪伴者 + 场景 + 媒介
```

## 2. 沟通演进

1. **能力辨析**：确认库输出 Prompt，不输出视频；用户需要复制 Prompt 到外部生成模型。
2. **网页展示**：建立能力、原理、输入/输出样例、上游样片和能力边界。
3. **场景扩展**：从儿童生日扩到原创角色、成长档案、习惯教育和家庭仪式。
4. **风格扩展**：证明纸艺只是媒介，补充黏土、织物、木偶、水彩、二维、三维、蜡笔、油画棒、水墨、皮影、像素和实景合成。
5. **创意方法**：停止继续堆模板，将方向拆成主题、关系、世界、叙事机制、情绪、风格和表达形态。
6. **对象迁移**：扩展到伴侣、父母长辈、朋友、自己、宠物、团队社群、品牌客户、城市文化和物件。
7. **情绪辨析**：把“被看见、归属、告别”等混合概念纠正为情绪状态、情绪需求、关系价值和转化结果四层。
8. **产品表达**：用八张概念图、八组 Prompt、八项效果预演和“输入 → 参与 → 留下”说明产品目标与主观意愿。
9. **真实人物测试**：以孩子喜欢奥特曼为真实需求，要求罗索、布鲁、格丽乔像家庭一样互动和主动陪伴。
10. **问题暴露**：用户指出生成孩子不是照片中的孩子、坐姿氛围差、需要动起来；动态构图测试仍然身份失真。
11. **入口方法**：确认单张斜侧照信息不足，建立多视角虚构身份板方法样例，并明确真人不能由模型补造缺失视角。
12. **视频复核**：用户提供的 10 秒测试片有运动感，但画幅、首帧、角色造型、角色数量和水印未达交付要求。
13. **最终抽象**：不再深入某一个奥特曼镜头，把研究收束为面向不同对象、场景和媒介的情绪价值与关系表达方法。

## 3. 价值体系

### 三类价值目标

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| 情绪价值 | 对方在当下如何被回应 | 被陪伴、被理解、被鼓励、被认可 |
| 关系价值 | 一段关系如何被看见和确认 | 亲子安全感、伴侣共同承诺、代际倾听、朋友共同走过 |
| 仪式价值 | 一个时刻如何被标记和留下 | 生日、纪念日、毕业、成长、重逢、告别、重新开始 |

### 四层设计链

```text
情绪状态 → 情绪需求 → 关系价值 → 转化结果
```

例子：

```text
害怕 / 孤单
→ 希望被陪伴
→ 确认“你不是一个人”
→ 更愿意迈出下一步
```

页面和产品只能设计过程与可观察信号，不能保证心理结果。建议观察：

- 用户是否愿意提供具体关系证据；
- 接收者是否能认出真实共同经历；
- 双方是否愿意补充、回应或共同完成；
- 产物是否会被再次打开、保存或赠送。

## 4. 示例设计原则

### 儿童与英雄

- 主观意愿：让孩子感到有人陪着他、相信他、愿意和他一起行动。
- 好的画面：牵手奔跑、英雄回望、共同完成任务、在害怕时挡在身边。
- 弱的画面：多个英雄和孩子排排站、所有人看镜头、孩子被当作合影道具。
- 推荐载体：动作短片、英雄来信、成长任务卡、互动绘本。

### 长辈与家人

- 主观意愿：让长辈感到被倾听、被感谢，家庭记忆仍有人接住。
- 关系证据：声音、旧照片、手艺、家庭路线、重复讲述的故事。
- 推荐载体：声音邮局、口述史短片、家族记忆地图。

### 伴侣

- 主观意愿：让对方知道普通日子也一直被认真记住。
- 关系证据：杯子、钥匙、通勤路线、便签、共同习惯。
- 推荐载体：日常档案馆、纪念日互动相册、双城同步日志。

### 宠物

- 主观意愿：保存无条件陪伴，或完成温柔告别。
- 关系证据：散步路线、睡觉位置、声音、玩具、喂食动作。
- 推荐载体：年度仪式盒、陪伴纪念册、声音与影像档案。

### 自己

- 主观意愿：让现在的自己得到确认，重新获得行动意愿。
- 关系证据：旧目标、已完成的小事、阶段物件、给未来的承诺。
- 推荐载体：未来回信、阶段路线册、双时空影像。

## 5. 奥特曼真实测试证据

| 资产 | 验证目的 | 结果 | 证据边界 |
| --- | --- | --- | --- |
| `ultraman-birthday-keyframe-v1.png` | 纸艺英雄生日概念 | 风格与生日氛围可表达 | 非真实孩子、非动态视频 |
| `ultraman-rb-family-companionship-v1.png` | 具名英雄的家庭陪伴关系 | 角色关系部分成立，孩子身份失败 | 不能代表用户孩子 |
| `ultraman-rb-running-motion-composition-test-v1.png` | 牵手跑步和跟拍构图 | 动作方向成立，身份仍未批准 | 不应直接动画化为最终片 |
| `identity-reference-input-board-sample-v1.png` | 多视角入口规范 | 能清楚展示正确输入结构 | 完全虚构人物，不可替代真实照片 |
| `multi-view-identity-to-ultraman-action-sample-v1.png` | 多视角到动作关键帧的方法 | 虚构身份保持优于单张斜侧照 | 只能说明方法，不能证明真人身份保证 |

### 发生身份偏差的原因

- 输入只有一张斜侧、头部倾斜、手遮挡耳侧的照片；
- 目标要求正面全身奔跑，模型必须推断未见的正脸、身体比例和服装形态；
- 全画面生成不是把原脸无损贴到新场景，而是重新合成所有像素；
- 动作变化越大，需要重画的信息越多；
- 多个具名角色同时出现进一步增加构图和身份控制难度。

### 关于入口照片的准确结论

好的入口照片依赖是**必要条件，不是充分条件**。

最低照片包：

- 自然光、无遮挡的正面半身；
- 45° 半身；
- 侧面；
- 目标服装的正面全身；
- 可选的 5–10 秒走路、转身或跑动视频。

不得要求模型凭空生成“缺失角度”并再把这些生成图当成真实身份依据。

## 6. 从图片到最终效果

### 推荐路线：真实短视频入口

适用于需要真实人物高度一致、动作明显的短片。

```text
真实人物实拍动作
→ 选择身份稳定的基础镜头
→ 合成或受控生成陪伴角色与环境
→ 逐镜头检查接触关系和遮挡
→ 配音 / 音乐 / 字幕 / 节奏
→ 画幅、水印、授权和隐私复核
→ 导出
```

### 备选路线：照片入口

```text
多视角身份包
→ 角色参考、色板和禁改项
→ 生成动作关键帧
→ 人工批准身份与构图
→ 每个 3–5 秒镜头单独图生视频
→ 身份、角色数量、经典造型和动作连续性复核
→ 剪辑与声音交付
```

### 用户测试片复核

已观察信息：约 10.0 秒、1280×720、24 fps、H.264/AAC。

- 通过：跟拍、奔跑和前进感；
- 未通过：目标竖屏、首帧保持、经典战衣细节、三位英雄全程出现、无水印；
- 判断：视频“动起来”了，但尚未达到人物一致、角色一致、构图一致和交付规格一致。

## 7. 上游与扩展能力的边界

| 层级 | 能力 | 当前状态 |
| --- | --- | --- |
| 上游 Skill | 信息采集、五套模板、三幕 Prompt、配音建议 | 已验证 |
| 本研究方法 | 场景/风格/对象/价值扩展、产品母型、创意组合 | 已沉淀为网页和文档 |
| 概念原型 | 场景图、风格对照、情绪产品图、真实测试图 | 可用于讨论和审批，不是产品结果 |
| 生产系统 | 身份控制、模型编排、逐镜头重试、合成、声音、导出 | 尚未由上游提供 |
| 商业交付 | 授权、隐私、质量指标、成本、售后 | 需要独立建设 |

## 8. 产品机会

可发展为：

- 亲子勇气与陪伴短片；
- 家庭声音档案与代际口述史；
- 伴侣日常证据档案；
- 宠物陪伴纪念与告别仪式；
- 自我回信、阶段复盘和未来对话；
- 毕业、退休、入职、离职和团队共同记忆；
- 品牌客户故事、社群贡献年鉴；
- 城市、老店、家乡、旧物与传统技艺的记忆再叙述。

更有价值的产品不是“输入照片，套一个动画风格”，而是：

```text
帮助用户发现想表达的关系意图
→ 收集只有他们拥有的证据
→ 选择恰当的象征、动作和媒介
→ 共同生成可参与、可保存的结果
```

## 9. 风险与原则

- 真实儿童素材必须由监护人授权并最小化保存；
- 任何虚构身份样例都必须明确标识，不能暗示是用户真实人物；
- 情绪产品不得承诺治疗、治愈或必然改变关系；
- 第三方 IP 的研究演示不代表拥有商业授权；
- 真实人物与具名角色的合成内容应考虑公开范围、误解风险和平台规则；
- 失败样例应作为方法证据保留，不应只展示看起来成功的画面。
